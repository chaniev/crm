# Нефункциональные требования

Доменный код: `NFR`. Источники миграции: MVP-ТЗ §12–13, backlog/done
(TASK-049, TASK-090, TASK-111, TASK-120).

### REQ-NFR-001. Мобильность интерфейса

**Статус:** реализовано

Интерфейс автоматически адаптируется к мобильным устройствам; без
горизонтальной прокрутки страницы, с мобильным представлением таблиц,
доступностью основных действий без наведения, touch-friendly элементами,
одноколоночными формами на узких экранах. Экран посещений удобен для работы
одной рукой. Проверка на ширинах 390 px, 768 px, 1440 px. Детали —
`docs/MOBILE_UI_CONTRACT.md`, скилл `crm-mobile-first-ui`.

**Изменения:**

- 27.08.2026 — новая (источник: MVP-ТЗ §12.1).

### REQ-NFR-002. Нагрузка и производительность

**Статус:** реализовано

До 10 000 клиентов и до 100 сотрудников. Списки клиентов, групп и посещений
поддерживают пагинацию или иной механизм без загрузки всех записей.

**Изменения:**

- 27.08.2026 — новая (источник: MVP-ТЗ §12.2).

### REQ-NFR-003. Безопасность

**Статус:** реализовано

Пароли — криптографический хеш. Cookie-based авторизация (HttpOnly, Secure в
production), CSRF-защита изменяющих запросов. Права и доступ к данным
проверяются на backend; frontend не единственное место проверки. Тренер не
получает через API персональные данные клиентов вне своего охвата.

**Изменения:**

- 27.08.2026 — новая (источник: MVP-ТЗ §12.3).

### REQ-NFR-004. Технологический стек и развертывание

**Статус:** реализовано

Backend — C#/.NET 10, frontend — React, СУБД — PostgreSQL, бот — Python.
Каждый сервис запускается в Docker; локально — docker-compose (backend,
frontend, PostgreSQL, бот). Секреты мессенджера не хранятся в репозитории.

**Изменения:**

- 27.08.2026 — новая (источник: MVP-ТЗ §13, BOT-ТЗ §14).

### REQ-NFR-005. Брендирование клуба

**Статус:** реализовано

Название клуба задаётся переменной окружения при деплое (fallback
«Gym CRM»), передаётся backend'ом во frontend; не редактируется из
интерфейса.

**Изменения:**

- 27.08.2026 — новая (источник: TASK-049).

### REQ-NFR-006. Актуальность данных интерфейса

**Статус:** реализовано

После CRUD-операций интерфейс обновляется автоматически без обязательной
кнопки «Обновить»; пользователь сразу видит актуальное состояние в списках,
карточках, на экране посещений.

**Изменения:**

- 27.08.2026 — новая (источник: MVP-ТЗ §10.1).
