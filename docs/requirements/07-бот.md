# Требования: Бот сотрудников

Доменный код: `BOT`. Источники миграции: BOT-ТЗ, backlog/done (TASK-001,

### REQ-BOT-001. Назначение и платформа

**Статус:** реализовано

Telegram-бот для коротких операционных действий сотрудников без замены
web-интерфейса. Платформенно-независимое ядро + адаптер Telegram (long
polling); бизнес-правила CRM — только в backend, бот работает через
internal Bot API с service-to-service авторизацией и не работает с базой CRM
напрямую. Только личные чаты; события групп/каналов игнорируются или
получают безопасный отказ. Тексты — на русском. Адаптер `MAX` — будущий
платформенный адаптер.

### REQ-BOT-002. Идентификация пользователя

**Статус:** реализовано

Логин/пароль CRM в чате не принимаются. Связь сотрудник ↔ Telegram `user_id`
задаётся администратором в карточке сотрудника; один `user_id` — у одного
сотрудника. Неизвестный `user_id` не получает CRM-данные (бот показывает его
Telegram ID и просит обратиться к администратору). Неактивный сотрудник и
сотрудник с обязательной сменой пароля не работают с ботом. Права в боте
соответствуют правам в web; смена роли, деактивация, изменение групп
применяются без синхронизации.

**Изменения:**

- 27.08.2026 — новая (источник: BOT-ТЗ §5; реализация TELEGRAM_BOT_IMPLEMENTED).

### REQ-BOT-003. Сценарии бота

**Статус:** реализовано

Role-aware меню (`/start`, `/id`). Реализованы сценарии:

- **Отметка посещаемости** — выбор даты (только разрешённые; для Главного
  тренера/Супер-администратора/Администратора — согласованный выбор прошлой
  даты, будущие запрещены всем) и группы из доступных, черновик отметок,
  сохранение одним действием с Idempotency-Key, краткий результат с
  предупреждениями по абонементу.
- **Поиск клиента** — по ФИО для всех ролей, по телефону для
  management-ролей; карточка в формате, разрешённом роли (срез Тренера —
  REQ-CLI-009).
- **Заканчивающиеся абонементы** (management-роли) — окно сегодня +
  10 календарных дней включительно, без просроченных.
- **Неоплаченные абонементы** (management-роли) — клиенты с текущим
  неоплаченным абонементом.
- **Отметка оплаты** (management-роли) — с явным подтверждением, записью в
  журнал; повторная отметка не выполняется.

Недоступные по роли разделы не отображаются и не выполняются командой.

**Изменения:**

- 27.08.2026 — новая (источник: BOT-ТЗ §6; объём — TELEGRAM_BOT_IMPLEMENTED,
  TASK-003).

### REQ-BOT-004. Идемпотентность и надёжность

**Статус:** реализовано

Повторные/устаревшие события платформы не дублируют изменяющие действия и
аудит-записи (ключ идемпотентности строится из детерминированных данных
события; таблица обработанных update'ов). При недоступности backend —
понятное сообщение. Health-check endpoint. Состояние диалогов хранится с
сроком жизни; при истечении сценарий безопасно завершается.

**Изменения:**

- 27.08.2026 — новая (источник: BOT-ТЗ §10.3, §13.1; TASK-001,
  TELEGRAM_BOT_IMPLEMENTED).

### REQ-BOT-007. Безопасность бота

**Статус:** реализовано

Не принимать/хранить пароль CRM; не отправлять секреты; не логировать
персональные данные сверх необходимого; ограничение частоты команд;
идемпотентная обработка callback-событий; явное подтверждение изменяющих
действий с риском ошибки; инвалидация доступа при деактивации сотрудника.
