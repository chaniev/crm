### REQ-GRP-002. Клиенты и тренеры в группах

**Решение:** принято

**Реализация:** реализовано

Клиент может состоять в нескольких группах; группа содержит несколько
клиентов; у группы может быть несколько тренеров. Назначенный тренер
получает права отметки посещений в этой группе. Главный тренер может быть
назначен тренером любой активной группы. Архивация группы блокируется
действующими и будущими привязками абонементов к ней.

### REQ-GRP-003. Недельный график группы

**Решение:** принято

**Реализация:** реализовано

График задаётся набором записей «день недели + время начала»
(минимум один день, без дублей) с общей длительностью занятия
1–180 минут. Время начала задаётся на каждый день недели отдельно.
Свободный текст расписания не используется. Расписание отображается как
локальное время без пересчёта часовых поясов.

**Границы и ограничения:**

### REQ-GRP-004. Календарь занятий

**Решение:** принято

**Реализация:** реализовано

Расписание — полноценный календарь конкретных занятий: серия занятий
(`LessonSeries`: дата старта, необязательная дата окончания, бессрочные
серии) с лениво материализуемыми занятиями (`LessonOccurrence`) со
стабильными идентификаторами. Поддерживаются несколько занятий группы в
один день, разовые занятия, перенос и изменение с тремя scope («только это»,
«это и будущие», «вся серия»), отмена и восстановление. Жизненный цикл
занятия: `Scheduled | Cancelled`. Отмена занятия с существующими отметками
посещений блокируется конфликтом. Точные пересечения занятий одной группы —
ошибка валидации; пересечения разных групп — неблокирующее предупреждение.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** REQ-GRP-003

**Изменения:**

### REQ-GRP-007. Task-first представление расписания

**Решение:** принято

**Реализация:** частично

На экране расписания каждое занятие сохраняет отдельную идентичность, но
занятия дня группируются по точному временному интервалу. Карточка прежде всего
показывает данные для выбора занятия и разрешённую операцию посещаемости;
редкие и опасные изменения доступны через вторичную поверхность. Интерфейс
показывает нейтральное наличие или отсутствие отметок только из backend-данных
и сохраняет дату, фильтры и позицию при переходе в занятие и обратно.

На mobile занятия внутри временной группы показываются компактными строками:
название группы, филиал, зал и тренер имеют приоритет над вторичными badges,
одновременно виден только один нейтральный attendance status. Операция
`Посещаемость` остаётся доступной одним нажатием, но повторяющиеся строки не
создают несколько конкурирующих filled-primary surfaces; изменение и редкие
действия доступны через `Ещё`. При `420 x 912` заполненный дневной список
показывает не менее четырёх полных строк и заголовок следующего временного
интервала без перекрытия bottom navigation.

**Границы и ограничения:**

- Представление не вводит собственные правила конфликтов, прав, просрочки,
  отмены, замещения или обязательности отметок.
- На поддерживаемых mobile и desktop размерах дата, навигация и основные
  действия остаются читаемыми без горизонтального переполнения.

**Связанные требования:** REQ-GRP-004, REQ-GRP-005, REQ-ATT-006, REQ-NFR-001
