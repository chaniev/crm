# Требования: «Клиенты, требующие внимания» и чат с клиентами

Доменные коды: `ATTN` (внимание), `CHAT` (чат). Источники миграции:
backlog/done (TASK-060, TASK-067, TASK-103, TASK-039).

### REQ-ATTN-001. Причины внимания

**Решение:** принято

**Реализация:** реализовано

Раздел «Внимание» (Главный тренер, Супер-администратор, Администратор)
показывает клиентов, требующих связи, по backend-состояниям:

- истекающий абонемент — не более 3 календарных дней до окончания;
- истёкший абонемент (показывается первым, тексты вида «Истёк 3 дня назад»);
- серия из 3 и более подряд явных пропусков (`Не был`); `Был` разрывает
  серию, «Не отмечено» и непроведённые занятия не учитываются; серия считается
  по клиенту (смена группы не разрывает) и может пересекать дату окончания
  абонемента.

Клиент с несколькими причинами показан один раз со всеми причинами.
Состояния вычисляет только backend. Действие «Связались» скрывает причину
пропусков до новой серии. Показываются ФИО, телефон, статус абонемента,
комментарий, ссылка на Telegram.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** нет

### REQ-CHAT-001. Чат с клиентами

**Решение:** принято

**Реализация:** реализовано

Двусторонний текстовый чат с клиентами через отдельный официальный
Telegram-бот клуба (не бот сотрудников). Чат — в карточке клиента.
Привязка Telegram-аккаунта клиента — по одноразовой deep-link/QR из CRM.
Читать переписку — Администратор и выше; отвечать — любой администратор.
Локальные статусы отправки («отправляется»/«отправлено»/«ошибка»);
in-app уведомления о новых сообщениях; просмотр переписки логируется.
Вложения, рассылки, импорт истории и delivery/read-receipts Telegram не
требуются.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** нет
