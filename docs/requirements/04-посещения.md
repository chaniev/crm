### REQ-ATT-001. Отметка посещения

**Решение:** принято

**Реализация:** реализовано

Посещение отмечается на экране посещений: пользователь выбирает группу и
дату (приводится к конкретному занятию), система показывает список клиентов
группы, напротив каждого — трёхсостоянийная отметка: `Не отмечено` / `Был` /
`Не был`. Отметку можно вернуть в «Не отмечено» (с аудитом). По умолчанию
список показывает только «Не отмечено»; переключатель открывает полный
состав со статусами. Массовое «отметить всех» отсутствует. Сохранение
посещений на будущие даты запрещено (backend).

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

### REQ-ATT-002. Привязка к занятию и snapshot времени

**Решение:** принято

**Реализация:** реализовано

Посещение привязывается к конкретному занятию (`LessonOccurrence`), а не к
паре «группа + дата». При первом создании отметки фиксируется snapshot
времени начала занятия (локальное время); далее snapshot не меняется при
изменении группы или графика. Snapshot используется в истории посещений,
упорядочивании «требующих внимания», расчёте пропусков — единая семантика в
web и боте.

**Границы и ограничения:**

### REQ-ATT-003. Права на отметку посещений

**Решение:** принято

**Реализация:** реализовано

- Главный тренер и Супер-администратор — любые группы всех филиалов, любая
  прошедшая дата.
- Тренер — только назначенные группы (постоянно + активные замещения) и
  только сегодня и два предыдущих дня; более ранние даты — только чтение.
- Администратор — только группы, для которых ему явно выдано разрешение
  главным тренером/супер-администратором; разрешение выдаётся в рамках
  филиала, выдача/отзыв аудируются. Эффективный охват возвращает backend в
  auth/session-контракте.

Будущие даты запрещены всем ролям.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

### REQ-ATT-006. Навигация и раздел «Внимание»

**Решение:** принято

**Реализация:** частично

«Посещения» — самостоятельный раздел `/attendance`. Тренер и Администратор
после входа попадают на «Посещения»; Главный тренер и Супер-администратор —
на раздел «Внимание» (`/attention`), недоступный Тренеру. Порядок навигации:
Посещения, Внимание, Расписание, Клиенты.

Landing `/attendance` показывает backend-authorized занятия текущего локального
дня, которые требуют действия: точный occurrence доступен для открытия и имеет
`unmarkedClientCount > 0`. `Cancelled`, `NotHeld`, недоступные и полностью отмеченные
занятия в списке не показываются. Строки упорядочены по времени начала; для каждой
видны данные выбора и точное количество клиентов со статусом `Не отмечено`, а одно
действие открывает отметку точного занятия.

После возврата из attendance workbench список автоматически актуализирует данные и
сохраняет контекст. Смена CRM-дня сама по себе не обновляет экран: в остальных
случаях обновление выполняется только по запросу пользователя. Некорректная отдельная строка
не скрывает остальные корректные занятия; экран сообщает о частичной загрузке. Empty, loading,
error и retry состояния остаются внутри раздела и не требуют обязательного перехода в `/schedule`;
пустой день и отсутствие доступных занятий пока не различаются.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.
