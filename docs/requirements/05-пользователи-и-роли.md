# Требования: Сотрудники и роли

Доменный код: `USR`. Источники миграции: MVP-ТЗ §2–3, backlog/done
(TASK-029, TASK-030, TASK-049, TASK-054, TASK-063, TASK-082, TASK-091,
TASK-096, TASK-105).

> В UI разделы называются «Тренеры» и «Администраторы»; в терминах продукта
> это сотрудники с учетными записями.

### REQ-USR-001. Роли

**Решение:** принято

**Реализация:** реализовано

Роли: Главный тренер (`HeadCoach`), Супер-администратор
(`SuperAdministrator`), Администратор (`Administrator`), Тренер (`Coach`).

- **Главный тренер** — доступ ко всему функционалу, включая финансовые
  отчёты, создание Супер-администраторов и назначение профессиональных
  абонементов; может быть назначен тренером любой активной группы.
- **Супер-администратор** — глобальная роль без привязки к филиалу: все
  права Администратора на все филиалы, управление Администраторами и
  Тренерами, отметка посещений во всех группах всех филиалов, выдача/отзыв
  групповых разрешений администраторам. Создаёт и назначает только Главный
  тренер; не может создавать Главного тренера и другого Супер-администратора.
- **Администратор** — управление клиентами, группами, абонементами,
  филиалом/залом своего филиала; отметка посещений только по выданным
  разрешениям (REQ-ATT-003).
- **Тренер** — отметка посещений в назначенных группах, ролевой срез данных
  (REQ-CLI-009).

Создание и смена ролей аудируются с old/new ролью и охватом филиала.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** REQ-ATT-003, REQ-CLI-009

### REQ-USR-002. Карточка сотрудника

**Решение:** принято

**Реализация:** реализовано

Поля: ФИО одним полем, логин, пароль, роль, признак обязательной смены
пароля, статус активности, платформа мессенджера и идентификатор
пользователя платформы (Telegram `user_id`; не более одного на сотрудника,
уникален среди сотрудников). Логин после создания не меняется. Удаление не
требуется — статус активности. Требования к сложности пароля не задаются.
Роль в формах не выбирается: определяется сценарием (Тренер → Coach;
Администраторы создаются через «Настройки → Администраторы», для
Администратора обязателен филиал, для Супер-администратора — нет; выбор
админ-роли виден только Главному тренеру из backend-разрешённых опций).

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** нет

### REQ-USR-003. Авторизация и первый пользователь

**Решение:** принято

**Реализация:** реализовано

Вход по логину и паролю. При первом входе обязательна смена пароля.
При развертывании создаётся пользователь с ролью Главный тренер и паролем
`12345678` с признаком обязательной смены пароля; логин задаётся
конфигурацией или значением по умолчанию. Cookie-based авторизация
(HttpOnly, Secure в production), CSRF-защита изменяющих запросов.

**Границы и ограничения:**
