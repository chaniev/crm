### REQ-CLI-001. Карточка клиента

**Решение:** принято

**Реализация:** реализовано

Для клиента хранятся: фотография, фамилия, имя, отчество, номер телефона,
дата рождения (необязательно), контактные лица (REQ-CLI-003), филиал,
группы, текущий абонемент с параметрами продажи (REQ-SUB-006), заметка
(REQ-CLI-005), история посещений, статус (REQ-CLI-002).

Обязательные поля при создании и редактировании: номер телефона и хотя бы
одно из полей ФИО. Клиент может быть создан без абонемента; абонемент
добавляется позже через карточку клиента.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** REQ-CLI-002, REQ-CLI-003, REQ-CLI-005, REQ-SUB-006

### REQ-CLI-004. Фотография клиента

**Решение:** принято

**Реализация:** реализовано

Хранится одна актуальная фотография; новая загрузка заменяет старую.
Файлы хранятся на стороне backend (не в БД; в БД только метаданные: путь,
MIME, размер, дата загрузки) в Docker volume. Допустимые форматы: JPEG, PNG,
WebP, HEIC, HEIF; недопустимые отклоняются с проверкой и расширения, и
MIME-типа; максимум 10 MB. HEIC/HEIF конвертируются в веб-совместимый формат.
Имя файла на диске генерируется backend. Рекомендуется уменьшение до 1024 px
по большей стороне. Доступ к фото проверяет backend: Главный тренер,
Супер-администратор и Администратор — все клиенты; Тренер — клиенты своих
групп (постоянные назначения и активные замещения).

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** нет

### REQ-CLI-007. Филиал и перевод клиента

**Решение:** принято

**Реализация:** частично

Клиент относится строго к одному филиалу. Нельзя записать клиента в группу
другого филиала. Перевод меняет филиал и состав групп клиента отдельной
операцией: старые назначения закрываются, выбранные назначения целевого
филиала открываются; целевые группы можно не выбирать.

Перевод не создаёт продажу или возврат, не прекращает и не переоформляет
абонемент автоматически, не меняет сумму, оплату и историческую атрибуцию.
Если новое назначение исключает целевые группы действующих или будущих
абонементов, backend отклоняет перевод с конфликтом; клиент, назначения,
абонементы и продажи остаются без изменений. Перенос целей абонемента
выполняется отдельной предусмотренной для этого операцией.

Администратор переводит только клиента своего текущего филиала. После
успешного перевода в другой филиал он получает подтверждение операции без
карточки клиента; последующее чтение и действия подчиняются актуальному
охвату REQ-USR-001. Повтор того же завершённого запроса подтверждает результат
без повторного перевода и раскрытия данных вне текущего доступа.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.

**Связанные требования:** REQ-USR-001, REQ-SUB-006

### REQ-CLI-009. Ролевой срез данных тренера

**Решение:** принято

**Реализация:** реализовано

Тренер видит только клиентов групп, где он назначен тренером (постоянно или
в активном замещении). Совпадение филиала само по себе не даёт доступа к
клиентам других групп. По клиенту Тренер видит: ФИО, фотографию, свои группы
клиента, элементы отметки посещения, предупреждение о проблеме с абонементом
без раскрытия полных данных, индикатор отсутствия оплаты. Тренер не получает
через API телефон, контактных лиц, полные данные абонемента и суммы.
Проверка — на backend.

**Границы и ограничения:**

- Отдельные ограничения не зафиксированы; применяются условия из текста требования.
