# Выбор агента для задачи CRM

Координатор выбирает профиль по предстоящей работе и учитывает требования карточки и согласованного плана. Одну задачу может выполнить один агент, если правила задачи допускают самостоятельную работу. Для изменений общего контракта проверки охватывают владельца контракта и всех затронутых потребителей. Бизнес-правила CRM и контракты API принадлежат backend. [Корневые правила](../AGENTS.md)

## Профили по типу работы

| Профиль | Когда привлекать |
|---|---|
| `dotnet-backend-specialist` | Для изменений доменной логики, прав доступа, API ASP.NET Core, транзакций и миграций данных. |
| `python-pro` | Для изменений Python-кода бота, типизации, зависимостей и интеграции с внутренним API CRM. |
| `ux-researcher` | Перед новым экраном или существенным изменением сценария. С помощью `crm-product-ux` описывает задачу пользователя, необходимые данные, переходы и восстановление после ошибки. |
| `ui-designer` | Для адаптивного прототипа и визуальной приёмки по `crm-interface-design`. Если визуальное направление открыто, готовит варианты для владельца по `crm-visual-direction`. |
| `react-specialist` | Для реализации согласованного интерфейса по `crm-react-implementation`, работы с формами, состоянием, загрузкой данных и производительностью React. |
| `test-automator` | Когда нужно покрыть конкретный риск регрессионными тестами, доработать тестовую инфраструктуру или устранить нестабильность тестов. |
| `refactoring-specialist` | Для ревью крупного структурного рефакторинга. Проверяет границы изменений и сохранение поведения и контрактов. |
| `docker-expert` | Для изменений Dockerfile, Compose, сборки образов и запуска контейнеров. При выпуске проверяет также резервное копирование и план отката. |

Определения профилей хранятся в репозитории. Объём проверок задают правила затронутых слоёв. [Профили](../.codex/agents) · [Backend](../backend/AGENTS.md) · [Бот](../bot/AGENTS.md) · [Frontend](../frontend/AGENTS.md) · [Развёртывание](../deploy/AGENTS.md)

## Отдельные проверки и замена исполнителя

| Ситуация | Как распределить работу |
|---|---|
| Обычная задача | Профиль предпочтителен. Если он недоступен, координатор может выполнить работу сам или поручить её доступному агенту. Явные требования карточки или плана к участникам и ревью сохраняют силу. |
| Приёмка нового экрана или существенного изменения сценария | Сравнить реализацию с согласованным прототипом и отдельно проверить поведение и доступность через `crm-interface-audit`. Оба прохода может выполнить тот же исполнитель. Навыки и результаты каждого этапа описаны в [процессе проектирования](DESIGN_PROCESS.md). |
| Крупный структурный рефакторинг | Ревью обязательно. Если доступен `refactoring-specialist`, привлечь его. При недоступности профиля ревью проводит другой проверяющий с компетенцией в затронутом коде. [Правила рефакторинга](../AGENTS.md#architecture-decision-workflow) |
| Выпуск на согласованный стенд | Координатор делегирует независимые проверки контейнеров, миграций и затронутых сервисов. Если именованный профиль недоступен, его проверку выполняет другой независимый агент в том же объёме. При повышенном риске отдельно проверяют регрессионное покрытие. SSH-команды, переключение сервисов и откат выполняет только координатор. [Порядок выпуска](../.agents/skills/deploy-project/SKILL.md) |
