# Подбор сервера для self-hosted развёртывания GLM-5.3

**Контекст:** команда разработки из 25 человек (разработчики, тестировщики, аналитики).
**Дата подготовки:** 2026-09-02. Цены ориентировочные, проверять у поставщиков/провайдеров на момент закупки.

---

## 1. Исходные данные по модели

GLM-5.3 — MoE-модель Z.ai: **~744B параметров всего, ~40B активных** на токен (тот же базовый
чекпоинт, что и GLM-5.2; улучшения 5.3 — пост-тренинг). Контекст до 1M токенов (131K — стандартный
рабочий режим).

Память под веса:

| Квантизация | Веса | Комментарий |
|---|---|---|
| BF16 | ~1,488 ГБ | только мульти-узел — не рассматриваем |
| **FP8** | **~744 ГБ** | рекомендуемый продакшен-вариант |
| AWQ INT4 | ~372 ГБ + 5–10% активации (~400–420 ГБ) | бюджетный, с потерей качества |

KV-кэш (FP16): ~20 ГБ на сессию с контекстом 128K; FP8-кэш вдвое меньше (~10 ГБ на 128K,
2,5–5 ГБ на рабочем контексте 32–64K).

## 2. Оценка нагрузки команды

Из 25 человек одновременно взаимодействуют с моделью обычно 30–50%, запросы разнесены во времени.
Планируемый пик: **8–12 параллельных потоков** (агентные сценарии с сабагентами — до 16).

Требования к памяти поверх весов: 100–150 ГБ KV-кэша на пик → **нужно ~250–350 ГБ свободной VRAM**
сверх весов модели.

Ориентир пропускной способности: ~150–200 ток/с агрегированно на 8-GPU узел при контексте 32K
(консервативная оценка; с батчированием в vLLM реально выше). При полном пике это 12–16+ ток/с
на пользователя — приемлемо для кодинг-агентов; при обычном разнесённом трафике заметно больше.

---

## 3. Основная рекомендация: один узел 8× NVIDIA H200

Всё умещается в один NVLink-домен, без мульти-узловой сложности.

| Компонент | Спецификация |
|---|---|
| GPU | 8× NVIDIA H200 SXM5 141 ГБ (NVLink, HGX) = 1,128 ГБ VRAM |
| CPU | 2× AMD EPYC 9004/9005 или Intel Xeon 6, суммарно 96–128 ядер |
| RAM | 1 ТБ DDR5 ECC (минимум 512 ГБ) |
| Диски | 2× 3.84 ТБ NVMe U.2 RAID1 (FP8-веса ~800 ГБ + чекпоинты/кэш); опционально +7.68 ТБ |
| Сеть | 2× 100 Гбит (ConnectX-7) на перспективу мульти-узла, 2× 25 Гбит в LAN |
| Питание | ~10–12 кВт, выделенная линия в стойке |
| ПО | Ubuntu 24.04, CUDA 12.8+, vLLM ≥ 0.19.0 или SGLang ≥ 0.5.10 |

Раскладка памяти: 744 ГБ веса + ~290–330 ГБ KV-кэш/активации → 16+ параллельных сессий
с контекстом до 128K; 1M-контекст — только 1–2 сессии одновременно.

**Параметры запуска:**

- FP8-веса + FP8 KV-кэш (`kv_cache_dtype fp8_e5m2`);
- `--max-num-seqs 24–32` (2× ожидаемого пикового параллелизма; для 1M-контекста — 1–2);
- `--max-num-batched-tokens ≥ 8192`, `--max-num-chunked-tokens 32768`;
- `--gpu-memory-utilization 0.92` (vLLM) / `--mem-fraction-static 0.88` (SGLang);
- доступ команде — OpenAI-совместимый эндпоинт + шлюз (LiteLLM) с API-ключами
  и rate-limit на пользователя.

## 4. Вариант 4× B200 — разбор

B200 SXM: ~180 ГБ используемой HBM3e на карту. 4× B200 = **~720 ГБ**, при utilization 0.92
доступно ~660 ГБ.

| Статья | Расчёт | Итог |
|---|---|---|
| FP8-веса | ~744 ГБ | ❌ не помещается — вариант исключён |
| AWQ INT4-веса | ~372 ГБ + активации | ✅ ~400–420 ГБ |
| Остаток под KV-кэш | 660 − ~410 | **~250 ГБ** |

~250 ГБ KV-кэша = ~25 сессий с контекстом 128K или 50–80 сессий на 32–64K — ёмкости для
25-person команды достаточно.

**Скорость:** пропускная способность памяти 4× B200 (~32 ТБ/с) близка к 8× H200 (~38 ТБ/с),
но INT4 вдвое уменьшает активные веса на токен (~20 ГБ против ~40 ГБ) — скорость на поток
сопоставима с 8× H200 FP8 или выше. Энергопотребление ~5–5,5 кВт против ~10–12 кВт.

**Плюсы:** компактнее и экономичнее по питанию, скорость на поток не хуже.

**Минусы (решающие):**

1. **INT4-квант** — потеря качества флагманской кодинг-модели, заметнее всего на сложных
   агентных задачах с длинным контекстом. Обязателен пилот на арендованной конфигурации до закупки.
2. **Нет серийных 4-GPU SKU** — платформа HGX для B200 восьми-GPU; 4× B200 только кастом
   через интегратора (закупка, гарантия, аренда сложнее).
3. **Экономия небольшая** — кастомный 4-GPU узел ~$180–300K против ~$300K ± 50K за серийный
   8× H200, при этом INT4 вместо FP8.

**Вывод:** как основной вариант не рекомендован; допустим только если INT4-качество подтверждено
пилотом и критичны мощность/место в стойке.

## 5. Альтернативы

| Вариант | VRAM | Квант | Годность для 25 чел. | Ориентир цены |
|---|---|---|---|---|
| **8× H200 (основной)** | 1,128 ГБ | FP8 | ✅ рекомендуемый | ~$300K ± 50K |
| 4× B300 (Blackwell Ultra, 288 ГБ) | 1,152 ГБ | FP8 | ✅ лучший «компактный» узел, если доступен | дороже 8× H200, проверять наличие |
| 4× B200 (кастом) | ~720 ГБ | только INT4 | ⚠️ после пилота качества | ~$180–300K кастом |
| 8× H100 / 4× H200 | 640 / 564 ГБ | INT4 | ⚠️ впритык: потолок контекста ~64K, меньше запас KV | ~$150–250K |
| 8× B200 | 1,440–1,536 ГБ | FP8 | ✅ premium: ×2 throughput, запас под 1M-контекст | ~$400–500K |
| GLM-5.3-Flash (320B-A18B) на 4× H200 | 564 ГБ | FP8 | ✅ если флагманское качество не обязательно | ~×3–4 дешевле |

Примечания:

- **4× B300** — единственный 4-GPU формат, где FP8-веса (744 ГБ) влезают без потери качества
  (1,152 ГБ, ~350 ГБ запас на KV) — вся ёмкость 8× H200 на половине карт и энергопотребления.
- **2× B200** (360–384 ГБ) — INT4-веса влезают почти без запаса под KV, для команды не годится.
- **GLM-5.3-Flash** (320B, 18B активных, 1M контекст, MIT) — вариант для быстрых задач
  (автодополнение) или как единственная модель при ограниченном бюджете; можно держать обе
  модели на 8× B200.

## 6. Стоимость (ориентиры 2026)

| Модель потребления | Оценка |
|---|---|
| Покупка сервера 8× H200 | ~$300K ± 50K |
| Кастомный 4× B200 | ~$180–300K (GPU $35–50K/шт.) |
| Аренда 8× H200 | ~$29.6/час on-demand (~$21.5K/мес 24/7); спот ~$19K/мес |
| Аренда 4× B200 | ~$16–64/час в зависимости от провайдера ($4–16/GPU-час) |
| Точка безубыточности vs API Z.ai | ~4.3 млрд выходных токенов/мес (API ~$4.40/M output) |

Если команда генерирует меньше ~4 млрд выходных токенов в месяц, экономического смысла в
self-hosted нет — он про контроль над данными, приватность кода и предсказуемость расходов.

## 7. Итоговое решение

1. **База:** один узел 8× H200 SXM, FP8 + FP8 KV, vLLM, `max-num-seqs 24–32`, LiteLLM-шлюз.
2. Если хочется компактный узел — **4× B300** (FP8 без компромиссов), а не 4× B200.
3. 4× B200 — только после пилотной валидации INT4-качества на реальных задачах команды.
4. Перед покупкой сравнить с API Z.ai по фактическому токен-обороту команды.

## 8. Альтернативные open-weight модели для локального развёртывания (сентябрь 2026)

GLM-5.3 — не единственный вариант. Ниже — актуальный ландшафт open-weight моделей,
привязанный к конфигурациям железа из разделов 3–5.

| Модель | Параметры (всего/актив.) | Веса | Железо | Лицензия | Комментарий |
|---|---|---|---|---|---|
| Kimi K3 (Moonshot) | 2.8T / ~104B | ~1.56 ТБ (нативный MXFP4) | 8× B300 (2.3 ТБ) или 4 узла 8× H100 | Modified MIT | топ open-рейтингов (~77% SWE-bench Verified), 1M контекст, vision; другой класс железа |
| DeepSeek V4-Pro | ~1.6T / ~49B | ~893 ГБ (микс FP4+FP8) | 8× H200 впритык, лучше 8× B200/B300 | MIT | лидер по raw SWE-bench Verified среди открытых |
| Kimi K2.6 | ~1T / ~32B | ~1 ТБ BF16 / ~500 ГБ квант | 8× H200 с квантом | Modified MIT | 58.6 SWE-Bench Pro |
| Qwen3-Coder 480B | 480B / 35B | ~480 ГБ FP8 | 4–8× H200 | Apache 2.0 | 55.4% SWE-bench, дешёвая инференс-стоимость, широкая линейка размеров |
| GLM-5.3-Flash | 320B / 18B | ~320 ГБ FP8 | 4× H200 | MIT | мультимодальная, 1M контекст |
| DeepSeek V4-Flash | ~300B / ~13B | ~167 ГБ (нативный микс FP4+FP8) | 2× H200 / 4× H100 | MIT | 1M контекст, самая дешёвая в среднем классе |
| MiniMax M2.5 | 230B / 10B | ~115 ГБ FP8 | 2× B200 / 4× H100 | MIT | ~100 ток/с нативно, лучшая скорость/рубль для агентных задач |
| gpt-oss-480b / 120b (OpenAI) | MoE | ~281 / ~65 ГБ (MXFP4) | 4× H100 / 1× H100 | Apache 2.0 | экосистема OpenAI, 120b — для рабочих станций |

Малый класс для автодополнения на рабочих станциях: Qwen3.x 27–32B, Devstral, Mistral Small 4.

**Выводы применительно к рекомендованному узлу 8× H200 (~1,030 ГБ usable):**

- Влезает всё, кроме Kimi K3; DeepSeek V4-Pro — впритык (893 ГБ весов, мало остаётся на KV-кэш,
  лучше 8× B200/B300).
- Узел универсален: либо GLM-5.3 в FP8, либо **две модели среднего класса одновременно**
  (например, Qwen3-Coder-480B + MiniMax M2.5 — кодинг + быстрые задачи).
- Если цель — максимум open-source качества (Kimi K3 / DeepSeek V4-Pro без компромиссов),
  класс железа меняется на 8× B300 (~2.3 ТБ) — это отдельный бюджет.
- Практичная стратегия: начать с одной флагманской модели, через LiteLLM-шлюз добавить
  облегчённую (MiniMax M2.5 / gpt-oss-120b) для массовых дешёвых задач и роутить по типу запроса.
