# TASK-060: Добавить просмотр истекших абонементов для администратора и главного тренера

## Status
risky

## Goal
Администратор и главный тренер могут быстро увидеть клиентов с истекшими абонементами через CRM-интерфейс, не нарушая backend-owned правила ролей, memberships и доступа.

## Context
В inbox зафиксировано требование: `добавить для администратора и главного тренера возможность просмотра истекших абонементов`. В проекте уже есть доменная логика абонементов и состояния истекшего абонемента, а также frontend-экран главной с блоком истекающих абонементов и клиентские фильтры/карточки.

## User role
администратор / главный тренер

## Problem
Администратору и главному тренеру нужна отдельная видимость клиентов, у которых текущий абонемент уже истек, чтобы вовремя продлевать абонементы и управлять клиентской базой. Без явной функции пользователю приходится искать такие случаи вручную или через косвенные признаки.

## Scope
- Проверить существующие backend-контракты и семантику состояния истекшего абонемента.
- Если backend-контракта недостаточно, добавить или расширить backend endpoint/filter так, чтобы состояние истекшего абонемента считалось на backend.
- Обеспечить доступ к просмотру для ролей `Administrator` и `HeadCoach` согласно существующей модели permissions/access scope.
- Обновить frontend-поверхность просмотра истекших абонементов: существующий список/фильтр клиентов, главный экран или другой уже принятый membership-сценарий.
- Показать понятные поля: клиент, тип абонемента, дата окончания, статус оплаты и действие перехода в карточку клиента, если оно доступно.
- Добавить backend/frontend regression coverage для доступа и отображения.

## Out of scope
- Изменение правил расчета истечения абонемента.
- Изменение правил покупки, продления, оплаты или списания посещений.
- Изменение ролей и общей модели permissions вне доступа к просмотру истекших абонементов.
- Массовые изменения данных или миграции без отдельного решения.
- Telegram-bot сценарии, если текущий продуктовый scope относится к CRM frontend.

## Constraints
- Backend owns CRM business logic: roles, permissions, memberships, attendance, validation semantics and ProblemDetails contracts.
- Frontend не должен вычислять истекший абонемент независимо от backend.
- Не расширять доступ ролей, кроме явно указанных `Administrator` и `HeadCoach`, без отдельного решения.
- Существующие сценарии истекающих и неоплаченных абонементов не должны сломаться.
- Если меняется backend contract, обновить все затронутые consumers.

## Acceptance criteria
- [ ] Administrator видит список или фильтр клиентов с истекшими абонементами.
- [ ] HeadCoach видит список или фильтр клиентов с истекшими абонементами.
- [ ] Роли без соответствующего доступа не получают новую видимость истекших абонементов.
- [ ] Состояние истекшего абонемента определяется backend-логикой, а не frontend-эвристикой.
- [ ] UI явно отличает истекшие абонементы от истекающих и неоплаченных.
- [ ] Пользователь может перейти из списка истекших абонементов в карточку клиента, если это разрешено доступом.
- [ ] Regression tests покрывают права доступа и отображение данных.

## Test checklist
- [ ] Запустить backend tests.
- [ ] Запустить `cd frontend && npm run lint`.
- [ ] Запустить `cd frontend && npm run build`.
- [ ] Добавить или обновить backend tests на доступ `Administrator`, `HeadCoach` и отрицательные роли.
- [ ] Добавить или обновить frontend tests/e2e на отображение истекших абонементов.
- [ ] Проверить, что существующие списки истекающих и неоплаченных абонементов продолжают работать.
