# TASK-063: Разрешить назначать главного тренера на любую группу

## Status
risky

## Goal
Пользователь с правом управления группами может назначить главного тренера тренером группы там, где обычные тренеры уже назначаются на группы.

## Context
В inbox зафиксирована заметка: `должна быть возможность назначить главного тренера на любую группу`.

Требование затрагивает роли, permissions, группы и trainer assignment. В текущей архитектуре backend владеет access scope и правилами назначения; frontend не должен самостоятельно обходить ограничения.

## User role
главный тренер / администратор

## Problem
Если главный тренер не доступен в списке тренеров для группы или backend отклоняет такое назначение, его нельзя поставить ответственным за группу, хотя продуктово это должно быть разрешено.

## Scope
- Проверить текущий backend contract для списка доступных тренеров группы и endpoint назначения тренеров на группу.
- Убедиться, что `HeadCoach` может быть валидным участником trainer assignment для любой активной группы, если это не противоречит существующим branch/group constraints.
- Обновить backend validation/access rules так, чтобы роль `HeadCoach` не исключалась из назначаемых тренеров.
- Обновить frontend options для формы группы, если список тренеров сейчас фильтрует только обычных `Coach`.
- Сохранить текущие ограничения для архивных/неактивных пользователей и групп.
- Добавить regression coverage на назначение `HeadCoach` в группу.

## Out of scope
- Изменение общей модели ролей или прав главного тренера.
- Создание нескольких главных тренеров, если это не поддерживается текущей моделью.
- Изменение правил доступа обычного тренера к клиентам вне назначенных групп.
- Изменение расписания, посещаемости или финансовых отчетов, кроме потребления корректной связи группа-тренер.
- Массовая миграция существующих групп.

## Constraints
- Backend owns roles, permissions, access scope, group membership and validation semantics.
- Frontend не должен обходить backend validation, добавляя `HeadCoach` только клиентским фильтром.
- Нельзя расширить обычным тренерам доступ к чужим группам.
- Назначение главного тренера должно уважать существующие статусы пользователя и группы.
- Если group assignment используется в отчетах или расписании, нужно проверить затронутые consumers.

## Acceptance criteria
- [ ] Главный тренер доступен в списке кандидатов для назначения на группу.
- [ ] Backend принимает назначение `HeadCoach` тренером группы там, где принимает обычного тренера.
- [ ] Для активной группы можно сохранить состав тренеров, включающий главного тренера.
- [ ] Обычные тренеры не получают новые права управлять чужими группами из-за этого изменения.
- [ ] Архивные или неактивные пользователи по-прежнему не назначаются, если такое ограничение уже существует.
- [ ] UI формы группы отображает главного тренера в выбранных тренерах без технических role labels.
- [ ] Regression tests покрывают назначение главного тренера на группу.

## Test checklist
- [ ] Запустить backend tests.
- [ ] Запустить `cd frontend && npm run lint`.
- [ ] Запустить `cd frontend && npm run build`.
- [ ] Добавить или обновить backend tests на options/assignment endpoint с `HeadCoach`.
- [ ] Добавить или обновить frontend tests/e2e на выбор главного тренера в форме группы, если рядом есть покрытие.
- [ ] Вручную проверить создание или редактирование группы с главным тренером в списке тренеров.
- [ ] Вручную проверить, что обычный тренер не получил доступ к управлению чужими группами.
