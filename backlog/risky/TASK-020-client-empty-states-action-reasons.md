## Goal

В полной карточке сотрудник видит, как начать первую отметку посещения, если она ему доступна. У действия с ограничением он может прочитать конкретную причину.

## Context

На 27.11.2026 в `main` (`208c7193`) уже доступны четыре действия при соответствующих правах. Сотрудник может оформить первый абонемент, выбрать группу, добавить контакт и загрузить фото сохранённому клиенту. Для существующих кнопок проверены мобильная компоновка и доступность нажатия. ## Acceptance criteria

- [x] Первый абонемент, выбор группы, добавление первого контакта и фото доступны сотруднику с соответствующими правами.
- [ ] Из загруженной пустой истории сотрудник с правом отметки может начать согласованный в TASK-016 сценарий. Для незагруженных данных, ошибки чтения и ограниченной видимости интерфейс не заявляет об отсутствии посещений у клиента.
- [ ] При двух контактах рядом с кнопкой видна причина ограничения. После удаления одного контакта можно добавить другой.
- [ ] Для затронутого ограничения доступа сотрудник получает конкретную подсказку у действия. По тексту, количеству записей и доступным кнопкам тренер не узнаёт скрытых данных о контактах, группах других тренеров или суммах продаж.
- [ ] Новые подсказки читаются на телефоне, разрешённый переход доступен с клавиатуры. Проверены сотрудник с правом отметки и сотрудник с ограниченным доступом.

## Required review and stop conditions

До реализации владелец домена/доступа проверяет на прототипе, какие причины можно показывать при соответствующем ответе сервера. Пустой ответ в ролевом срезе не доказывает, что у клиента вообще нет данных. Если для подсказки приходится угадывать причину отказа или раскрывать скрытые сведения, остановить эту часть до согласования контракта. Переход к первой отметке зависит от решения TASK-016. Лимит контактов уже принят в REQ-CLI-003.
