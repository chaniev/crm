# TASK-066: Показывать по умолчанию клиентов без отметки посещения

## Status
risky

## Goal
Ускорить отметку посещений: после выбора группы по умолчанию показывать только клиентов со статусом `Не отмечено`, убирать клиента из этого списка после успешного сохранения отметки и сохранять возможность просмотреть полный состав группы со всеми статусами.

## Context
После реализации трёх состояний посещения в `TASK-064` список группы показывает клиентов независимо от статуса. Новая заметка уточняет рабочий сценарий: основной список должен фокусироваться на ещё не обработанных клиентах, а уже отмеченные клиенты — исчезать из него после успешного сохранения. Для проверки результата пользователю нужен переключатель на полный список группы.

## User role
Администратор / главный тренер / тренер с backend-разрешением на отметку посещений.

## Problem
Пользователь вынужден визуально отделять клиентов со статусом `Не отмечено` от уже обработанных. По мере отметки список не сокращается, поэтому сложнее понять, кто ещё требует действия. При этом полное скрытие отмеченных клиентов лишило бы пользователя возможности проверить сохранённые статусы.

## Scope
- На вкладке `Посещения` после выбора группы и даты включать представление `Не отмечено` по умолчанию.
- В представлении `Не отмечено` показывать только клиентов, у которых для выбранных группы и даты отсутствует сохранённая отметка.
- После успешного сохранения статуса `Был` или `Не был` удалять клиента из текущего представления сразу либо после явного обновления данных — выбрать один согласованный UX-вариант при реализации и покрыть его тестами.
- Предоставить явное переключение на полный список состава выбранной группы.
- В полном списке показывать каждого клиента и его текущий статус: `Не отмечено`, `Был` или `Не был`.
- Корректно обновлять оба представления после установки, изменения или сброса отметки в `Не отмечено`.
- Сохранить backend-driven permissions и существующие attendance/audit/membership semantics.

## Out of scope
- Изменение значений и смысла состояний `Не отмечено`, `Был`, `Не был`.
- Изменение правил списания или восстановления разового посещения.
- Изменение audit semantics, ролей, permissions или access scope.
- Массовая отметка клиентов.
- Переработка вкладки `Абонементы` и других экранов CRM.

## Constraints
- Backend остаётся источником истины для attendance-состояния, permissions, memberships и audit semantics.
- Frontend не должен считать локально сохранение успешным до подтверждения backend.
- При ошибке сохранения клиент не должен исчезать из списка `Не отмечено`; ошибка должна оставаться видимой и допускать повтор действия.
- Смена группы или даты должна показывать актуальные данные соответствующего занятия.
- Полный список должен включать весь доступный пользователю состав группы, не обходя backend access scope.
- Не смешивать задачу с несвязанным рефакторингом attendance API или главной страницы.
- Реализацию выполнять в отдельной ветке от актуального `main`.

## Acceptance criteria
- [ ] После выбора группы и даты по умолчанию открыт список клиентов со статусом `Не отмечено`.
- [ ] Клиенты со статусами `Был` и `Не был` не отображаются в списке `Не отмечено`.
- [ ] После успешного сохранения `Был` или `Не был` клиент исчезает из списка `Не отмечено` согласно выбранной UX-модели обновления.
- [ ] При ошибке сохранения клиент остаётся в списке `Не отмечено`, а пользователь видит ошибку и может повторить действие.
- [ ] Пользователь может переключиться на полный список выбранной группы.
- [ ] В полном списке присутствуют все доступные клиенты группы и для каждого показан один из статусов: `Не отмечено`, `Был`, `Не был`.
- [ ] Изменение отметки в полном списке обновляет отображаемый статус без рассинхронизации с backend.
- [ ] После сброса отметки в `Не отмечено` клиент снова появляется в представлении `Не отмечено`.
- [ ] Переключение представления не меняет выбранные группу и дату и не создаёт лишних записей посещения.
- [ ] Существующие правила списания/восстановления посещений, аудит и permissions не изменены.

## Test checklist

- [ ] Добавить/обновить e2e-сценарий: выбрать группу и дату, отметить клиента, проверить исчезновение из default-списка и наличие корректного статуса в полном списке.
- [ ] Проверить смену группы и даты, а также permissions для администратора, главного тренера и тренера.
