# TASK-070: Создать управляемый справочник абонементов

## Status
risky

## Goal
Администратор может добавлять варианты абонементов в справочник и отключать устаревшие варианты без изменения истории продаж.

## Context
Нужен справочник абонементов с активным/неактивным статусом. После создания нельзя менять сумму так, чтобы это ретроспективно ломало отчёты.

## User role
Администратор / главный тренер.

## Problem
Фиксированный набор типов абонементов нельзя безопасно пополнять, а редактирование цены существующего варианта может исказить финансовую историю.

## Scope
- Спроектировать backend-owned каталог вариантов абонементов.
- Разрешить создание и перевод варианта в активный/неактивный статус.
- Показывать активные варианты при новой продаже, сохраняя чтение исторических неактивных вариантов.
- Защитить цену уже созданного варианта от небезопасного изменения либо ввести версионирование/создание нового варианта.
- Добавить управление справочником в согласованный раздел настроек.

## Out of scope
- Пересчёт существующих продаж.
- Массовая замена абонементов клиентов.
- Изменение возвратов, заморозок и списаний.

## Constraints
- Продажа должна хранить стабильную историческую сумму независимо от будущего состояния каталога.
- Backend владеет membership, financial report, permissions и validation semantics.
- Нельзя удалять вариант, если на него ссылается история.

## Acceptance criteria
- [ ] Уполномоченный пользователь может создать вариант абонемента.
- [ ] Неактивный вариант недоступен для новой продажи, но корректно виден в истории.
- [ ] Цена существующей продажи не меняется при любых разрешённых действиях со справочником.
- [ ] Запрещённое изменение возвращает согласованный ProblemDetails.
- [ ] Изменения справочника фиксируются в audit trail.

## Test checklist
- [ ] Проверить создание, деактивацию и повторное чтение варианта.
- [ ] Проверить новую продажу и историческую продажу после деактивации.
- [ ] Проверить неизменность финансового отчёта.
- [ ] Запустить backend tests, frontend lint и build.
