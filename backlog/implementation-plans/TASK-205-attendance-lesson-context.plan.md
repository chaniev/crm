## Goal

На маршруте `/attendance/{lessonOccurrenceId}?lessonDate=YYYY-MM-DD` сотрудник до первой отметки видит группу, дату и фактический интервал выбранного занятия. Явный возврат ведёт в тот список, из которого открыли состав. Прямая ссылка работает и в новой вкладке.

## Decisions and contracts

- Эталон — [принятый прототип](/backlog/mockups/TASK-205-attendance-lesson-context/README.md). Название группы, под ним дата вида «20 ноября 2026» и локальный интервал «08:00–09:00». Кнопка возврата справа при достаточной ширине, под интервалом на узком экране. Длинное название переносится целиком. Шапка прокручивается с составом. Меню демонстрационных сценариев принадлежит прототипу.
- Для каждого входа вызвать параллельно `getScheduleLesson(id, date, signal)` и `getAttendanceLessonClients(id, date, signal)`. Из первого ответа взять `groupName`, `lessonDate`, `startTime`, `endTime` и `allowedActions`. Второй предоставляет состав, текущее состояние строк, дату и группу. Расписание уже отдаёт конечное время перенесённого, разового и регулярного занятия. Область чтения состава проверяется его собственным endpoint.
- При смене пары ID/дата сразу убрать прежний контекст и строки. Показать их вместе после успеха обоих запросов при разрешённом `viewAttendance`. Сверить ID и дату деталей с маршрутом, группу и дату деталей с `groupId` и `trainingDate` состава. Если состав явно вернул ID занятия и `lessonDate`, сверить и их. Учитывать, что ID в модели состава может быть подставлен маппером из параметра запроса. Пропущенные или противоречивые сведения дают состояние ошибки. Устаревший ответ после смены маршрута или повтора игнорировать.
- При загрузке доступен возврат. При временном сбое «Повторить» повторяет чтение той же пары. После успеха восстановить фокус на названии. Для 403/404 любого чтения и отказа в просмотре показать «Занятие недоступно» и возврат. Обработку истёкшей сессии оставить общей. До подтверждения контекста действия отметки недоступны.
- Разрешение редактирования приходит из `allowedActions.editAttendance`. Учесть также явный запрет `canEditAttendance`, если он присутствует в ответе состава. При отказе в редактировании показать состав только для просмотра и понятную причину. Серверный код `attendance-date-unavailable` сам по себе охватывает несколько случаев. Подпись о будущем занятии допустима, когда его дата позже серверного `today`; для общего отказа достаточно «Занятие доступно только для просмотра». Компоненты отображают серверное решение. Успешная запись и её повтор используют существующий POST для текущей пары.
- Переход из расписания использует `returnToSchedule` и его snapshot (дата, фильтры, прокрутка, якорь). Для перехода из «Посещений» сохранить признак этого входа в записи истории самого занятия, привязанный к его паре ID/дата. На исходной записи уже хранится snapshot списка. «К занятиям на сегодня» возвращает на эту запись с повторной загрузкой списка и существующим выбором фокуса — исходная строка, следующая доступная или действие обновления. Без подтверждённого источника заменить текущий маршрут на `/attendance`. При возврате из карточки клиента восстановить то же занятие, режим и фокус строки, сохранив путь обратно в исходный список.

## Scope

### In
Шапка конкретного занятия, согласованная загрузка двух ответов и возврат при всех трёх входах. Обновление русских подписей и регрессий этих переходов.
### Out
Изменения списка клиентов, фильтра состава, массовых действий, алгоритма сохранения и исторического снимка времени. Общий формат дат ведётся в TASK-175. Миграции данных не требуются, для отката достаточно предыдущей версии frontend.

## Implementation slices

1. В тестах экрана и маршрута воспроизвести потерю контекста и отсутствие явного возврата. Подготовить реальные по форме ответы деталей и состава, включая ответ состава без опционального `canEditAttendance`.
2. В режиме конкретного занятия связать чтение деталей с открытием состава. Поставить принятую шапку на место общей подписи и даты. Провести загрузку, отказ, повтор и режим чтения через этот же маршрут. После отметки сохранить действующее обновление состава.
3. Провести действие возврата от навигации приложения до шапки. Проверить исходный список и исчезновение завершённого занятия, фильтр расписания, путь через карточку клиента и прямой вход.
4. Сверить работающий экран с прототипом, провести отдельную проверку доступности и записать результат в REQ-ATT-001 и журнал требований. Статус широкого требования пересматривать с учётом остальных его критериев.

Проверить ответы в обоих порядках, переключение занятия при незавершённом запросе, временную ошибку и повтор, 403/404, несовпадение пары/группы и отсутствие устаревших кнопок.
- Будущее занятие с серверным запретом доступно для чтения даже без флага в составе. При отказе в чтении состава скрыты и строки, и сведения занятия. Проверить отсутствие POST в этих состояниях. На доступном занятии проверить три состояния и точные ID/дату отправки.
- `attendance-today-worklist.spec.ts` и `group-schedule.spec.ts`: через рабочие входы открыть разные занятия, вернуться с клавиатуры и касанием; проверить URL, фильтры, фокус и позицию. Завершить последнюю отметку и вернуться к обновлённому списку, где исходная строка исчезла. Отдельно открыть прямую ссылку в новой вкладке и проверить локальный возврат. Геометрию проверять с фактическим viewport проекта, включая 390/768/1440 и целевые iPhone.
- `client-profile-context-navigation.spec.ts`: обновить ответы для маршрута занятия, пройти состав → клиент → состав → исходный список. Обновить только затронутые фикстуры существующих потребительских тестов.

### Expected red evidence
На исходном экране обе пары занятий показывают «Посещаемость занятия» и дату. Проверка группы с интервалом и действие «К расписанию» падают. При независимой ошибке чтения деталей старый экран способен показать строки после успешного чтения состава. Зафиксировать исходное падение на поведении экрана.

Для двух мобильных проектов выбраны исполнимые specs из текущего `testMatch`. Новые мобильные случаи разместить вне блоков с принудительным viewport 390 px. ### Manual evidence
Сравнить шапку, перенос названия и положение возврата с сохранёнными снимками при одинаковой ширине. Отдельно пройти клавиатурой вход, повтор, возврат и переход через клиента. Проверить видимый фокус, озвучиваемые состояния и доступность первой отметки на узком экране. Указать фактические браузеры и устройства в отчёте приёмки.

### Regression barrier
Один и тот же клиент в двух занятиях одной группы за день: шапка различает интервалы, POST содержит выбранный ID и дату, возврат восстанавливает источник. При смене занятия и ответах в обратном порядке прежняя шапка и прежние строки недоступны для отметки.

## Risks and stop conditions

Если для легитимного занятия реальный API расписания не возвращает детали при доступном составе, зафиксировать роль, обе пары запроса/ответа и вернуть вопрос о серверном контракте в планирование. Подбор занятия по группе, старой дате или времени из истории может привести к отметке другого занятия.
