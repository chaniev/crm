## UX contract

Пользователь — Администратор своего филиала либо Супер-администратор,
который предварительно выбирает филиал. Сценарий — перенос готового XLSX
с компьютера или телефона через текущую сессию CRM. Backend определяет доступ,
целевую группу, пригодность строк и результат записи.

Цель: выбрать целевую группу и файл, однократно отправить, увидеть подтверждённое
число созданных клиентов либо исправимые ошибки. Неопределённый результат
отличается от подтверждённого отказа. Первичный путь: вкладка → филиал (SA) →
название группы → файл → «Импортировать» → результат. Для Admin выбор филиала
отсутствует. Парсинга, предпросмотра строк и выбора mapping в браузере нет.

| Класс | Операция | Размещение |
| --- | --- | --- |
| Основная | Импортировать | Видимая кнопка после полей, одна на форму |
| Частая | Выбрать/заменить XLSX, исправить группу | Постоянные поля с подписями |
| Вторичная | Новый импорт после известного исхода | В панели результата; очищает файл |
| Исключительная | Сохранить номер и сверить неизвестный исход | Постоянное предупреждение, кнопка копирования |

Измеримые критерии: один POST на запуск и двойной клик; ошибка файла показывает
все возвращённые issues с Excel-номерами; pending/result сохраняются при смене
вкладки; unknown никогда не выглядит как «создано 0». Backend permission scope
управляет видимостью; UI не выводит права из названия роли.

## Visual brief

- Surface: существующие SettingsScreen и PageTabsPanel; новая вкладка «Импорт».
- Character: рабочая форма в текущих Mantine/Onest, без декоративного введения.
- Hierarchy: назначение → файл → действие; при ошибке или unknown результат
  получает первичный визуальный приоритет.
- Density: три подписанных поля для SA, два поля и фиксированный филиал для Admin.
- Reuse: PageLayout/PageSection/PageTabsPanel, shared Button, Mantine fields,
  semantic warning/danger/success tokens. Новая библиотека/тема не требуется.
- References: [DESIGN](/frontend/DESIGN.md); реальные SettingsScreen, recipes,
  typography и CSS импортированы в изолированный preview без изменения приложения.
- Avoid: повтор заголовка «Импорт» под активной вкладкой, таблица предпросмотра,
  технический UUID как вводимое поле, обещание отмены серверной операции.
- Selection: насколько быстро видны назначение и исход; число переходов;
  достижимость формы и инструкции восстановления на узком экране.

## Implementation contract для A

Контракт соответствует выбранным screenshots A; композиция и порядок полей
не изменены. Pending, диалог ухода, success и полный отчёт ошибок дополняют
показанные ready/unknown состояния текстовой спецификацией ниже.

### Композиция и адаптация

1. Сохранить текущий порядок разрешённых вкладок, добавить «Импорт» последней.
   Существующая mobile-сетка в две колонки сохраняется; нечётная последняя
   вкладка занимает строку целиком, подписи видимы без горизонтального скролла.
2. Под вкладками без нового заголовка: постоянный результат/предупреждение,
   затем филиал, название группы, файл, предупреждение о новых карточках,
   кнопка запуска. В состоянии ready панель результата отсутствует.
3. Форма в одну колонку до 600 px на desktop, на mobile по ширине контента.
   Не добавлять пустую вторую колонку, карточки статистики или intro.
4. Филиал SA — подписанный Select из разрешённого lookup; Admin — фиксированные
   название и подпись «Филиал». Имя филиала берётся из разрешённого справочника,
   в session его сейчас нет. Ошибка справочника не превращается в глобальный выбор.
5. Название группы — TextInput, не autocomplete и не создание группы;
   подпись сохраняется после ввода. Файл — FileInput/native picker с именем
   и возможностью замены. Длинное имя переносится без скрытия расширения.
6. Основная кнопка после полей, в обычном потоке без sticky/footer панели.
   Поведение на compact-height, safe-area и клавиатуре следует
   [mobile acceptance](/.agents/skills/crm-mobile-first-ui/references/mobile-acceptance.md).

### Состояния и переходы

| Состояние | Отображение и доступные действия |
| --- | --- |
| Empty/ready | При отсутствии обязательных значений запуск недоступен; постоянные подписи объясняют недостающее |
| Lookup loading/failed | LoadingState либо ErrorState и «Обновить»; введённая группа/файл сохранены |
| OwnBranch/null | Причина отсутствия назначения; запуск недоступен, чужой филиал выбрать нельзя |
| Pending | «Импорт выполняется», номер операции с копированием; поля и отправка заблокированы, нет фиктивного процента и «Отменить импорт» |
| Подтверждённый 4xx | Сообщение формы/файла, все ошибки строк; контекст сохранён; исправление/замена файла открывают новый запуск |
| Success | «Создано N клиентов», филиал/группа и номер операции; «Новый импорт» очищает файл, сохраняет назначение; повтор требует выбора файла |
| Unknown | «Результат не подтверждён», номер операции и инструкция сверки; нет кнопки повтора и автоматического POST |
| Отозванный доступ | Вкладка скрыта по новому session scope; нет success/rollback утверждения для уже отправленной операции; пока Settings доступен, recovery-контекст остаётся без формы. Принудительный redirect/login не блокируется и может потерять локальный номер; сверка по сохранённому номеру либо actor/time/action |

Ошибки с `field` и без row показываются у соответствующего поля; ошибки строк
— списком «Строка 7 · Телефон» и backend message, без значений ячеек. Полный
список доступен в потоке страницы без вложенного скролла. Generic ошибки без
extensions используют существующий safe feedback; после сетевого обрыва,
5xx или некорректного 2xx остаётся unknown, а не сообщение об откате.

### Навигация, фокус и восстановление

- Состояние запроса живёт выше размонтируемой панели Tabs; смена вкладки не
  отменяет запрос и не отправляет его снова. Pending/unknown сохраняют номер.
- Для управляемого SPA-ухода кнопками раздела/смены пароля/выхода из Settings
  в pending/unknown предусмотрен диалог «Импорт мог
  завершиться. Сохраните номер операции для проверки» с номером, копированием,
  «Остаться» и «Уйти со страницы». Уход не отменяет backend-транзакцию.
  Logout API вызывается только после выбора ухода. Browser Back/Forward идут
  через существующий popstate без гарантированного диалога; новый протокол
  блокировки history не вводится. Постоянное предупреждение pending/unknown
  заранее предлагает сохранить номер, Back/Forward никогда не повторяют POST.
  Reload/закрытие использует стандартное предупреждение браузера, которое
  не гарантируется на mobile; постоянного browser ledger нет. Принудительная
  потеря доступа/сессии обходит guard и не задерживает перенаправление.
- После возврата на вновь открытую страницу автозапуска нет. Если номер потерян,
  сверка возможна по сотруднику/времени/действию, без обещания автоматического
  восстановления формы. Пользователь повторяет импорт только после сверки исхода.
- Проверка журнала: фильтры сотрудник/период/«Импорт клиентов завершён» → детали
  записи → сравнение полного EntityId/operationId и createdCount. Поиска по UUID
  текущий API не имеет. Admin обращается к SA/HeadCoach; аудит ему не открывается.
  Отсутствие записи во время выполнения не подтверждает откат.
- После submit поле с локальной ошибкой получает фокус; для row errors фокус
  на summary, список связан с ним. Status — `aria-live=polite`; error summary
  объявляется один раз. Фокус не переносится в неактивную вкладку при ответе.
- Tab-порядок соответствует визуальному; dialog сначала фокусирует «Остаться»,
  Escape закрывает его, фокус возвращается на trigger. Copy сообщает результат
  и оставляет полный номер выделяемым при недоступном Clipboard API.

## Проверки и ограничения evidence

Screenshots — rendered concepts с synthetic названием группы и файла,
не готовый импорт. Начальные состояния и unknown сняты в Chromium на 390×844
и 1440×1200. Production code, endpoints и БД не изменены. Реальные XLSX не
загружались. Runtime API/PG, WebKit/iPhone, browser chrome/keyboard и полный
shell-navigation gate выполняются после реализации и не заявляются пройденными.
В 14 снятых состояниях не обнаружены горизонтальный page overflow или
JavaScript page errors. Макеты визуально просмотрены; это geometry/evidence
концептов, не приёмка реализованного workflow. Pending/dialog и полный набор
ошибок заданы текстовым контрактом, на screenshots показаны ready/unknown.

Выбранное направление: **A**. Approval: **пользователь, владелец продукта,
2026-11-15**, точная формулировка приведена в разделе «Выбор владельца».
Самокритика: самая слабая часть — ручная сверка unknown через роль с аудитом;
из текущего API нельзя получить отдельный подтверждённый статус операции.
Новые status endpoint/таблица и расширение прав в этот дизайн не входят.
