# TASK-043: Уточнить календарный вид расписания

## Status
needs-clarification

## Goal
Понять, какой именно календарный вид нужен для расписания CRM и какие сценарии он должен поддерживать до изменения текущего экрана расписания.

## Context
В inbox есть заметка: "модифичировать отображение расписания - сделать по аналогии с календарем задач популярных планировщиках задач". Сейчас `TASK-035` уже реализовал отдельный раздел `Расписание` как недельный список групповых занятий. Новая заметка просит другой, календарно-планировочный способ отображения, но не фиксирует конкретный формат.

## User role
администратор / тренер / все пользователи CRM

## Problem
Текущий список по дням может быть недостаточно похож на привычный календарь задач, но без уточнения вида можно случайно добавить лишние функции: drag-and-drop, переносы, личные тренировки, конфликты или редактирование расписания.

## Scope
- Уточнить референсы популярных планировщиков и желаемый вид: день, неделя, месяц или timeline.
- Уточнить, должен ли календарь оставаться read-only или поддерживать редактирование.
- Уточнить, какие данные показывать в ячейке занятия.
- Уточнить, как календарь должен вести себя на mobile.
- Уточнить, нужны ли фильтры по филиалу, залу, тренеру, группе или типу группы.

## Out of scope
- Немедленная реализация нового календаря.
- Переносы, отмены, замены тренера и conflict resolution без отдельной backend task.
- Изменение backend schedule rules.
- Drag-and-drop редактирование до явного продуктового решения.

## Constraints
- Backend владеет schedule validation and access scope.
- Frontend не должен добавлять frontend-only правила конфликтов или переносов.
- Значимое UX-изменение требует участия `ui-designer` перед реализацией.
- Нужно сохранить решения `TASK-035`: расписание доступно всем CRM users, строится из backend group schedule data, `trainingStartTime` отображается как локальное `HH:mm`.

## Acceptance criteria
- [ ] Зафиксирован целевой календарный вид первой версии.
- [ ] Зафиксировано, read-only это отображение или редактируемый календарь.
- [ ] Зафиксированы поля, которые видны в календарной карточке занятия.
- [ ] Зафиксированы требования к mobile/tablet.
- [ ] Зафиксированы нужные фильтры и сортировка.
- [ ] После уточнения создана ready/risky задача для frontend implementation.

## Test checklist

- [ ] Проверить, что будущая задача не добавляет backend schedule rules frontend-only.
