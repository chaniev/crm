# TASK-016: Довести быстрые действия в карточке клиента

## Status
needs-clarification

## Requirements
- REQ-CLI-001 — changes
- REQ-USR-001 — constrains
- REQ-SUB-003 — constrains
- REQ-ATT-001 — constrains
- REQ-ATT-003 — constrains

## Goal
В карточке клиента доступны ожидаемые быстрые действия, а каждое действие соблюдает права, статус клиента и backend-валидацию.

## Context
Нужно довести быстрые действия: отметить посещение, оформить абонемент с оплатой, добавить в группу, редактировать, отправить в архив. По принятому REQ-SUB-003 оформление уже означает оплату; отдельная операция «принять оплату» из исторической заметки выведена из обращения.

## User role
администратор / тренер

## Problem
Сейчас карточка клиента не дает быстрый доступ ко всем частым операциям или делает их недостаточно ясно.

## Scope
- Проверить существующие frontend actions и backend endpoints.
- Добавить недостающие quick action controls.
- Подключить действия к существующим flows.
- Показать disabled/unavailable state там, где действие запрещено.
- Добавить regression coverage на основные действия.

## Out of scope
- Изменение бизнес-правил посещений, абонементов, оплат, групп или архива.
- Создание новых backend semantics без отдельной contract task.

## Constraints
- Backend владеет permissions, memberships, attendance, payments и validation semantics.
- Frontend не должен сам решать, кому разрешено действие, если это не отражение backend-состояния.
- Архивация и оплата требуют особой проверки UX и прав.

## Acceptance criteria
- [ ] В карточке есть быстрые действия: отметить посещение, оформить абонемент с оплатой, добавить в группу, редактировать, отправить в архив; каждое открывает соответствующий разрешённый сценарий.
- [ ] Недоступные действия не позволяют обойти backend restrictions.
- [ ] Ошибки backend отображаются через существующий error UX.
- [ ] Основные quick actions покрыты frontend tests или ручным checklist.

## Test checklist
- [ ] Запустить `cd frontend && npm run lint`.
- [ ] Запустить `cd frontend && npm run build`.
- [ ] Проверить actions для ролей с правами и без прав.
- [ ] Проверить клиента без абонемента, с абонементом и в архиве.

## AI safety
- Safe for autonomous implementation: no
- Risk level: high
- Reason: задача затрагивает посещаемость, абонементы, оплату, группы, архив и permissions.

## Clarification questions

- Какие из пяти действий нужны уже в краткой карточке списка, а какие достаточно оставить в полной? Какую форму открывать первой при действующем абонементе — покупку или продление?
- С какого состояния экрана посещений начинать, когда у клиента несколько подходящих занятий или ни одного? REQ-ATT-001 требует выбрать конкретное занятие перед отметкой, REQ-ATT-003 задаёт доступные группы и даты.

## Сверка 21.11.2026

В полной карточке уже есть редактирование, архивирование с подтверждением и оформление абонемента. Из секции групп можно перейти в редактирование. В краткой карточке кнопки абонемента, сообщения и посещения вызывают один обработчик `onOpen(selectedClientId)`. Тест проверяет открытие профиля и доступность кнопок с клавиатуры. Аудит 20.11 подтвердил лишний переход до формы абонемента. [Краткая карточка](../../frontend/src/features/clients/list/ClientPreviewPanel.tsx) · [Тест](../../frontend/src/features/clients/list/ClientPreviewPanel.test.tsx) · [Полная карточка](../../frontend/src/features/clients/ClientDetailScreen.tsx)

Задача нужна для прямого запуска операций. Статус изменён на `needs-clarification` до выбора точек входа и назначения кнопок. Ошибочный выбор занятия или формы продажи затрагивает посещения и деньги. На прототипе проверить достигнутое состояние для тренера и администратора с разным доступом. Новую кнопку оплаты эта задача не вводит. Структура вкладок рассматривается в [TASK-019](TASK-019-client-card-tabs.md).
