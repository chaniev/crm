# TASK-093: Уточнить единое расположение кнопок добавления

## Status
needs-clarification

## Goal
На согласованных экранах CRM кнопка добавления занимает одно предсказуемое место относительно заголовка, фильтров и других действий.

## Context
В inbox отмечено, что на одних экранах controls добавления прижаты к левому краю, а на других находятся рядом с фильтрами. Конкретные экраны, эталонное расположение и поведение на разных ширинах не указаны.

## User role
Администратор / главный тренер / суперадминистратор / неизвестно.

## Problem
Непоследовательное расположение primary action замедляет повторяющиеся операции, однако без списка затронутых экранов и выбранного паттерна Codex пришлось бы самостоятельно решить продуктовую и UX-семантику.

## Scope
- Составить согласованный перечень экранов с операцией добавления.
- Для каждого экрана зафиксировать текущий контейнер кнопки: page header, section header, standalone toolbar или filter panel.
- Выбрать единое целевое положение primary add action на desktop, tablet, mobile и compact-height.
- Зафиксировать порядок кнопки добавления относительно refresh, secondary actions и фильтров.
- После ответов подготовить отдельную implementation-ready UI-задачу с UX-контрактом, mobile-first спецификацией и regression matrix.

## Out of scope
- Перемещение кнопок до согласования перечня экранов и целевого паттерна.
- Изменение доступности операций, permissions или backend contracts.
- Переработка состава и поведения фильтров.
- Унификация secondary и destructive actions, если они не нужны для размещения primary add action.

## Constraints
- На каждом состоянии экрана должна оставаться одна визуально доминирующая primary action.
- Primary add action нельзя скрывать в overflow menu.
- На mobile действие должно оставаться достижимым с учётом safe area, Safari chrome и software keyboard.
- Нельзя размещать кнопку внутри filter panel только ради визуального выравнивания, если она не относится к фильтрации.
- Реализация должна использовать shared Mantine/Onest pattern, а не отдельные CSS-исключения для каждого экрана.

## Acceptance criteria
- [ ] Зафиксирован полный перечень экранов первого этапа.
- [ ] Для desktop/tablet выбран один эталонный контейнер и alignment кнопки добавления.
- [ ] Для mobile и compact-height определено видимое и достижимое положение primary action.
- [ ] Зафиксирован порядок add, refresh, secondary actions и filters.
- [ ] Определены исключения для экранов, которым общий паттерн не подходит, с причиной.
- [ ] На основе решений создана отдельная implementation-ready задача без открытых продуктовых вопросов.
