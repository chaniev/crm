# TASK-059: Уточнить объединение разделов Главная и Посещения

## Status
needs-clarification

## Goal
Понять, как именно должны быть объединены разделы `Главная` и `Посещения`, чтобы дальнейшая реализация не изменила навигацию и сценарии отметки посещений наугад.

## Context
В inbox зафиксирована короткая заметка: `объединить главная и посещение`. В текущем frontend есть отдельные экраны `HomeDashboard` и `AttendanceScreen`, а также отдельные секции маршрутизации `Home` и `Attendance`.

## User role
неизвестно

## Problem
Из заметки не ясно, требуется ли объединить пункты меню, перенести функциональность посещений на главную, встроить виджеты главной в посещения, изменить landing screen для ролей или только переименовать/сгруппировать разделы.

## Scope
- Уточнить ожидаемую информационную архитектуру после объединения.
- Уточнить роли, для которых должно измениться меню или стартовый экран.
- Уточнить, что должно произойти с текущим URL `/attendance` и доступом к отметке посещений.
- Уточнить, какие блоки текущей главной должны остаться, исчезнуть или переехать.
- После уточнения перевести задачу в `tasks-ready` или `risky`.

## Out of scope
- Реализация объединения до уточнения требований.
- Изменение backend-правил посещаемости, ролей или permissions.
- Изменение семантики отметки посещений.
- Удаление существующих пользовательских сценариев без явного решения.

## Constraints
- Backend остается источником истины для attendance, roles, permissions и access scope.
- Frontend не должен дублировать правила доступа к посещаемости.
- При будущей реализации следовать `frontend/AGENTS.md` и сохранить Mantine/Onest.
- Не ухудшить быстрый сценарий отметки посещений для тренеров и администраторов.

## Acceptance criteria
- [ ] Определено, что означает `объединить`: общий пункт меню, общий экран, перенос блоков или изменение landing screen.
- [ ] Определено, для каких ролей меняется навигация и стартовый экран.
- [ ] Определено, что происходит с текущим разделом `Посещения` и URL `/attendance`.
- [ ] Определено, какие блоки текущей `Главной` остаются доступными.
- [ ] После уточнения создана реализационная задача с понятным scope и test checklist.

## Test checklist
- [ ] После уточнения определить нужные frontend unit/e2e проверки для маршрутизации и навигации.
- [ ] После будущей реализации запустить `cd frontend && npm run lint`.
- [ ] После будущей реализации запустить `cd frontend && npm run build`.
- [ ] После будущей реализации проверить сценарий отметки посещений для ролей с доступом.
