# TASK-113: Уточнить сортировку расписания по типу групп

## Status
needs-clarification

## Goal
Пользователь быстро находит занятия нужного типа, не теряя временной порядок расписания.

## Context
В расписании уже отображаются типы групп, цветовая легенда и количество занятий по типам. Фильтры поддерживают филиал, зал, тренера и группу, но не тип группы. Занятия сортируются прежде всего по времени.

Фраза «Сортировка по типу групп» не определяет экран и операцию: фильтрацию, группировку внутри дня или замену основной хронологической сортировки.

## User role
Тренер / администратор / главный тренер; экран требует подтверждения.

## Problem
Неверная интерпретация может нарушить основной time-first сценарий расписания или добавить дублирующий control рядом с существующей легендой.

## Scope
- Подтвердить целевой экран: расписание или реестр групп.
- Выбрать одну операцию: filter by type, grouping by type или переключаемый primary sort.
- Определить single/multi-select и порядок типов, если выбран filter/grouping.
- Определить поведение на mobile, tablet и desktop и связь с существующей легендой и reset filters.
- Сохранить хронологический порядок занятий внутри выбранного типа или секции.

## Out of scope
- Реализация до выбора операции.
- Изменение справочника типов групп.
- Frontend-only бизнес-приоритеты типов.
- Изменение backend schedule semantics и conflict logic.

## Constraints
- Существующая легенда остаётся metadata, пока продукт явно не делает её интерактивной.
- Active filter/grouping state должен быть видимым, доступным и сбрасываемым.
- На mobile новый control не должен создавать вторую action-only строку или горизонтальный page scroll.
- Если legend chips становятся интерактивными, нужны button semantics, visible focus, active state и hit area не меньше `44 x 44px`.

## Acceptance criteria
- [ ] Подтверждён целевой экран.
- [ ] Выбрана ровно одна основная операция: filter, grouping или sort mode.
- [ ] Определены правила single/multi-select, reset и сохранения state.
- [ ] Хронологический порядок внутри типа явно сохранён или обоснованно заменён.
- [ ] Определена роль существующей легенды и исключено дублирование controls.
- [ ] Описаны empty-after-filter, loading, error и reset states на обязательных mobile размерах.

## Test checklist
- [ ] После уточнения добавить unit tests на выбранную операцию и time-first порядок внутри результата.
- [ ] Добавить Playwright-сценарий выбора типа, пустого результата и reset.
- [ ] Проверить keyboard/focus semantics и touch targets.
- [ ] Проверить отсутствие horizontal overflow на `390`, `420`, `440`, `768` и `1440px`.
