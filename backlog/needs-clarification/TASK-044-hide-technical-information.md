# TASK-044: Уточнить удаление технической информации со всех экранов

## Status
needs-clarification

## Goal
Определить, какая именно техническая информация должна быть скрыта из CRM UI, на каких экранах она видна и какие данные должны остаться доступными для диагностики или аудита.

## Context
В inbox есть короткая заметка: "убрать со всех экранов техническую информацию". В проекте есть разные типы потенциально технических данных: ID объектов, JSON старых/новых значений в журнале, служебные коды ошибок, технические поля в описаниях, route/API terminology и diagnostic text.

## User role
все пользователи CRM

## Problem
Технические данные в пользовательском интерфейсе могут мешать работе и выглядеть непрофессионально, но формулировка "со всех экранов" слишком широкая: нужно понять, какие именно элементы считаются техническими и где их убирать нельзя.

## Scope
- Составить список экранов и элементов, где пользователь видит техническую информацию.
- Разделить технические элементы на те, которые нужно скрыть, заменить человекочитаемым текстом или оставить для audit/debug.
- Уточнить правила для журнала событий: показывать ли ID объекта и raw JSON.
- Уточнить правила для ошибок backend ProblemDetails: что показывать пользователю, а что оставлять для диагностики.
- После уточнения создать одну или несколько локальных implementation tasks.

## Out of scope
- Немедленная правка всех экранов без инвентаризации.
- Удаление audit data из backend.
- Скрытие информации, которая нужна для compliance, поддержки или восстановления действий.
- Широкий UI-редизайн unrelated screens.

## Constraints
- Backend остается source of truth для audit, validation and ProblemDetails contracts.
- Нельзя скрывать важные причины ошибок так, чтобы пользователь не понимал следующий шаг.
- В журнале событий может быть информация, необходимая для аудита; ее нельзя удалять без решения владельца продукта.
- Возможное пересечение с `TASK-018` и `TASK-020` нужно проверить при уточнении.

## Acceptance criteria
- [ ] Зафиксирован список экранов, где сейчас видна техническая информация.
- [ ] Зафиксированы примеры данных, которые нужно убрать или заменить.
- [ ] Зафиксировано, что делать с ID объектов, raw JSON, техническими ошибками и служебными enum/code labels.
- [ ] Зафиксированы исключения, где технические данные должны остаться доступны.
- [ ] После уточнения создана bounded ready/risky задача или несколько задач по конкретным экранам.

## Test checklist
- [ ] Проверить пересечение с активными frontend UX-задачами.
- [ ] Проверить, что будущие задачи не ломают audit/diagnostic requirements.
