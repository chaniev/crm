# TASK-112: Уточнить однодневный режим расписания

## Status
needs-clarification

## Goal
Пользователь может сосредоточиться на расписании одного дня, не теряя недельный контекст и хронологический порядок занятий.

## Context
На mobile экран `/schedule` уже показывает временную сетку выбранного дня с переключателем дней недели, а на tablet/desktop — недельную сетку из семи колонок. Текущий backend и завершённые TASK-043/TASK-045 описывают повторяющийся недельный шаблон, а не календарь конкретных дат.

Исходная заметка «добавить возможность открывать расписание на 1 день» не уточняет, нужен ли однодневный режим этого недельного шаблона на desktop/tablet или новый календарный сценарий конкретной даты.

## User role
Тренер / администратор / главный тренер.

## Problem
Без продуктового решения реализация может либо продублировать уже существующий mobile-сценарий, либо незаметно превратить недельный шаблон в dated calendar и изменить смысл расписания.

## Scope
- Зафиксировать, что означает «1 день»: один weekday недельного шаблона или конкретная календарная дата.
- Определить устройства, на которых пользователь переключает режимы `Неделя / День`.
- Определить начальный выбранный день и сохранение выбора при фильтрации, обновлении, возврате и смене viewport.
- Определить место переключателя относительно фильтров и временной сетки.
- После решения подготовить UX-контракт и UI specification для существующего read-only schedule flow.

## Out of scope
- Реализация до выбора семантики дня.
- Редактирование, перенос, отмена занятий или drag-and-drop.
- Изменение schedule conflict logic.
- Добавление календарных дат и навигации по неделям без явного продуктового решения.

## Constraints
- Backend остаётся источником данных, permissions и schedule semantics.
- Внутри дня занятия сохраняют сортировку по времени начала.
- Текущие фильтры, refresh, loading, empty, stale/error и permission-restricted states должны сохраняться.
- На `390 x 844`, `420 x 912`, `440 x 956`, `912 x 420` и `956 x 440` не должно быть page-level horizontal scroll или nested-scroll trap.
- Tabs, filters и actions должны иметь hit area не меньше `44 x 44px` и видимый focus.
- Нельзя смешивать эту задачу с активной TASK-106 про читаемость параллельных занятий.

## Acceptance criteria
- [ ] Зафиксировано: однодневный режим относится к weekday-шаблону или к конкретной дате.
- [ ] Определены доступность и default mode на mobile, tablet и desktop.
- [ ] Определено сохранение выбранного дня при filters, refresh, back/forward и responsive transition.
- [ ] Описан primary path `Расписание -> выбор режима/дня -> занятия дня -> смена дня`.
- [ ] Описаны loading, empty day, filter-empty, stale/error и retry states.
- [ ] Для `390 x 844`, `420 x 912`, `440 x 956`, `912 x 420`, `956 x 440`, `768px` и `1440px` заданы измеримые responsive acceptance criteria.

## Test checklist
- [ ] После уточнения добавить component tests для выбора дня и сохранения состояния.
- [ ] Добавить Playwright-сценарии filters/refresh/back и пустого выбранного дня.
- [ ] Проверить keyboard path, `aria-selected`, visible focus и arrow/Home/End navigation.
- [ ] Проверить long group/type/hall/trainer names и отсутствие горизонтального overflow.
