# TASK-076: Уточнить изменение фильтра по пользователям в журнале

## Status
needs-clarification

## Goal
Уточнить, какое изменение требуется для фильтрации журнала действий по пользователям, с учетом того что такой фильтр уже присутствует в текущем интерфейсе и API.

## Context
В inbox зафиксирована заметка: «В журнале фильтр по пользователям». Текущий экран `Журнал` уже содержит searchable-фильтр `Пользователь` со значениями ФИО и логина, а backend принимает `userId` и отдает список пользователей, у которых есть записи аудита.

## User role
главный тренер / администратор

## Problem
Из заметки неясно, требуется ли добавить уже существующий фильтр, исправить его работу, изменить набор доступных пользователей или поддержать выбор нескольких пользователей. Без уточнения реализация рискует продублировать существующую функциональность или изменить ожидаемое поведение журнала.

## Scope
- Уточнить ожидаемый сценарий фильтрации по пользователям.
- Проверить конкретную проблему или недостающее поведение на текущем экране журнала.
- После уточнения определить, достаточно ли frontend-изменения или требуется корректировка backend-контракта фильтрации.

## Out of scope
- Реализация изменений до уточнения ожидаемого поведения.
- Изменение audit semantics, состава событий или прав доступа к журналу.
- Переработка остальных фильтров журнала.

## Constraints
- Backend остается source of truth для audit semantics, ролей и permissions.
- Фильтрация должна использовать стабильный идентификатор пользователя, а не совпадение по отображаемому ФИО.
- Нельзя ослаблять доступ к журналу для ролей без `canViewAuditLog`.

## Acceptance criteria
- [ ] Зафиксировано, чего не хватает в текущем фильтре `Пользователь`.
- [ ] Определено, нужен одиночный или множественный выбор пользователей.
- [ ] Определено, какие пользователи должны попадать в список вариантов.
- [ ] Если это дефект, приведены шаги воспроизведения и ожидаемый результат.
- [ ] После уточнения задача может быть переведена в `tasks-ready` или `risky` либо закрыта как уже реализованная.

## Test checklist
- [ ] После уточнения добавить или обновить frontend component/e2e-проверку фильтра журнала.
- [ ] Если меняется API, добавить или обновить backend integration-тест фильтрации по пользователю.
- [ ] Вручную проверить сценарий под главным тренером и администратором.

- [ ] Нужен выбор одного пользователя или нескольких пользователей одновременно?
- [ ] Должны ли в списке быть только пользователи с записями журнала или все пользователи CRM, включая неактивных?
