## Goal
Сотрудник создаёт группу и начальное расписание одним нажатием. Ошибки
объясняют действительную причину, доступный филиал определяется сервером,
уход через действия приложения требует подтверждения потери ввода.
Кнопки браузера не защищаются: при уходе введённые данные теряются.

## Context
[Источник и экспертные наблюдения](../processed/2026-11-19-group-creation-request.md).
Одна кнопка, предупреждение перед уходом, разрешённый уход во время создания,
проверка списка при неизвестном результате и игнорирование неблокирующих
предупреждений приняты владельцем 19.11.2026. Последующим уточнением владелец
исключил защиту кнопок браузера: без предупреждения, блокировки и сохранения ввода.
[Прототип A.2 без сводки](../mockups/TASK-203-group-create-single-action/README.md)
проверен и согласован владельцем 19.11.2026. Технический контракт также согласован;
задача готова к реализации.

## User role
Главный тренер, Супер-администратор и Администратор в существующей области доступа.
Тренер не получает возможности создавать группы.

## Problem
- Preview требует лишнего обязательного нажатия даже без предупреждений.
- Общий справочник филиалов ошибочно используется как перечень разрешённых
  мест создания; серверный отказ маскируется общим сообщением.
- Пустые дни приводят к ошибкам уже заполненных зала и длительности.
- Возврат к списку уничтожает ввод без подтверждения.

## Scope
- Одна отправка формы, последовательная внутренняя проверка и запись.
- Отдельные серверные варианты филиала/зала для создания; общие справочники сохраняются.
- Исправление серверной валидации пустого расписания и отображения причин отказа.
- Предупреждение при уходе с изменённой формы через действия приложения;
  разрешённый подтверждённый уход во время создания с потерей ввода.
- Кнопки браузера, включая Back/Forward, работают без защиты формы;
  уход теряет ввод, сохранение и восстановление черновика не добавляются.
- Понятные состояния ожидания, ошибки и неподтверждённого результата;
  неблокирующие предупреждения не показываются и не прерывают создание.
- Локальные подписи необязательного окончания и тренеров, удаление отдельного
  блока обязательного preview и нижней дублирующей сводки; поля, Mantine и Onest сохраняются.

## Out of scope
Редактирование существующих групп/серий и назначений; новый движок пересечений;
расширение прав; защита браузерной навигации; автосохранение и восстановление черновика;
перепроектирование остальных частей формы, палитры и всего приложения; bot, миграции и deployment.

## Acceptance criteria
- [ ] Нижняя сводка, повторяющая выбор в полях создания группы, отсутствует.
- [ ] Обычное создание требует одного нажатия «Создать группу»; success только после записи.
- [ ] Ошибка preview не отправляет create; повторные нажатия не запускают вторую цепочку.
- [ ] Администратор не получает чужие филиалы как доступные варианты создания;
  подмена филиала запросом по-прежнему отклоняется сервером.
- [ ] При пустых днях нет ложных ошибок заполненных зала/длительности;
  фокус и прокрутка указывают на действительную проблему.
- [ ] После подтверждённой ошибки введённые данные остаются, повторная попытка доступна.
- [ ] Уход с изменённой формой через действия приложения требует
  предупреждения: «Остаться» сохраняет ввод, «Выйти без сохранения» теряет его.
  Автоматические начальные значения не считаются пользовательскими изменениями.
- [ ] Кнопки браузера, включая Back/Forward, не вызывают предупреждение и не
  блокируются формой, в том числе во время создания; ввод при уходе теряется
  и приложением не восстанавливается. Уход не вызывает повторной записи.
- [ ] Во время создания подтверждённый уход через приложение разрешён; предупреждение объясняет,
  что уход не отменяет операцию и группа может быть создана после него.
- [ ] При неизвестном результате доступны сообщение и «Проверить список групп»;
  повторная отправка создания из этого состояния не предлагается.
- [ ] Неблокирующие предупреждения игнорируются без показа и подтверждения;
  блокирующая ошибка останавливает создание и отображает причину.
- [ ] Проверены неизменность токена/payload, ошибки прав, пустые варианты, ошибки
  загрузки и отсутствие автоматического повтора записи при неизвестном результате.
- [ ] Интерфейс соответствует выбранному прототипу; выполнен отдельный аудит сценария.
- [ ] После интеграции актуализированы REQ-GRP-008, затронутые карточки и CHANGELOG.
