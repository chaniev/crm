# TASK-163: «Внимание» — плотность списка и actions в карточке

## Status
ready

## Requirements
- REQ-ATTN-001 — constrains
- REQ-NFR-001 — constrains

## Goal
«Внимание» работает как плотный рабочий список обзвона: на `420 x 912` до
первой карточки тратится не более двух управляющих строк, на экран помещается
минимум 5–6 клиентов, действия в карточке не обрезаются.

## Context
Анализ 2026-08-30 (`artifacts/screenshots/all-screens/03-attention-top.png`)
показал: до первой карточки ~284px (35% экрана) — строка подзаголовка, строка
сводок («Всего N», «Просрочен N»), строка статуса списка; карточки ~140–150px
с радиусом ~24px и тенью — на экране всего 3 клиента; внутри карточки три
равнозначные кнопки в ряд, на 420px это ~120px на кнопку с зазорами 6–8px и
обрезанными подписями. Backend-состав данных карточки (ФИО, телефон, статус
абонемента, комментарий, Telegram, причины) определяется REQ-ATTN-001 и не
меняется.

## User role
Главный тренер / супер-администратор / администратор, обрабатывающий список
клиентов, требующих связи, с телефона.

## Problem
Список обзвона показывает 3 клиента на экран и требует прокрутки на каждого;
три равные кнопки в карточке конкурируют и не помещаются по ширине.

## Scope
- Свести надписания/сводки к максимум двум строкам над контентом: убрать
  отдельную строку подзаголовка и строку сводок, перенести счётчики в
  локатор/строку состояния списка без потери их смысла.
- Перевести карточки на list-row surface (TASK-160): компактная строка
  ~90–110px, тон/бордер вместо тени, радиус ≤ 16px; состав данных
  REQ-ATTN-001 сохраняется полностью.
- Действия: одна видимая основная (контакт/«Связались» по решению в задаче) +
  остальные за одной иконкой-меню с доступными именами; ни одна операция не
  теряется, «Связались» сохраняет семантику REQ-ATTN-001.
- Проверить filter/status surface и фокус-возврат в новой плотности.

## Out of scope
- Изменение backend-расчёта причин внимания, статусов или действия
  «Связались».
- Добавление новых действий/статусов/фильтров сверх контракта.
- Detail клиента и чат.

## Constraints
- Backend остаётся источником данных и состояний; frontend не выводит новых
  причин.
- Все цели ≥ 44×44px, ≥ 8px интервалы; карточка остаётся keyboard-operable.
- Токены TASK-160 потребляются после его интеграции; до того задача может
  использовать локальные значения, совпадающие с будущими токенами.

## Acceptance criteria
- [ ] На `420 x 912` минимум 5 карточек клиентов полностью видимы; на
      `390 x 844` — минимум 4.
- [ ] До первой карточки — не более двух строк управления; счётчики списка
      доступны и не потеряны.
- [ ] Все данные REQ-ATTN-001 (ФИО, телефон, статус, комментарий, Telegram,
      причины) присутствуют; длинные значения переносятся/обрезаются с
      доступом к полному тексту.
- [ ] Ровно одна доминантная кнопка в карточке; прочие действия достижимы
      одним нажатием через меню; подписи действий не обрезаются.
- [ ] Операционные состояния (loading/empty/error/retry) сохранены.

## Test checklist
