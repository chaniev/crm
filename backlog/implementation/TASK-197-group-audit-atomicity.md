# TASK-197: Атомарность обновления группы и аудита

## Status
implementation

## Requirements
- REQ-AUD-001 — implements

## Goal
При отказе обязательного аудита PUT /groups/{id} не сохраняет изменение группы; повтор после устранения сбоя сохраняет изменение и ровно одну запись аудита.

## Source and approval
Пользователь проекта, 16.11.2026, текущий чат: «выполни каждый шаг предлагаемого рефакторинга», «после каждого шага комить локально изменения», «новый рефакторинг начинай после успешного завершения предыдущего шага», «после всех шагов рефакторинга запусти существующие тесты и добейся их позелеления».
Предшествующее предложение начиналось с отдельного исправления: запись изменения группы и обязательного аудита в одной транзакции, сначала тест отказа аудита.
Это восстановление существующего invariant backend/AGENTS.md, без нового продуктового решения, API или схемы.

## Scope
Только активный UpdateGroupAsync, PostgreSQL regression, REQ-AUD-001 evidence. Остальные предложенные рефакторинги выполняются следующими отдельными шагами после успешной проверки и локального коммита.

## Acceptance
- Отказ аудита откатывает поля группы и timestamp; предыдущий аудит сохранён.
- Повтор работает и создаёт ровно одну запись с old/new state.
- Сохраняются блокировки доступа и повторная проверка доступа при формировании ответа.
