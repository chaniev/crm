# TASK-204: Находить клиента по сочетанию фамилии и имени

## Status
implementation

## Requirements
- REQ-CLI-008 — implements
- REQ-USR-001 — constrains

## Goal
Поиск по отображаемым частям ФИО находит существующего доступного сотруднику клиента без повторного ввода одной фамилии.

## Context
CLI-01: в аудите 20.11.2026 запрос «Алексеев Алексей» дал пустую выдачу; «Алексеев» нашёл «Алексеев Алексей Дмитриевич». Это runtime-наблюдение локального стенда, причина ещё не установлена. В текущем ClientQueryEndpoints.cs функции ApplyFullNameSearch и ApplyUnifiedSearch уже разбивают запрос на слова: нельзя заранее считать причиной отсутствие токенизации.

## User role
Все сотрудники с разрешённым доступом к списку клиентов.

## Problem
Пользователь повторяет поиск и может ошибочно решить, что клиента нет.

## Scope
- Воспроизвести парные запросы на одном наборе данных, роли и фильтрах; сопоставить введённую строку, HTTP-запрос, ответ и выдачу.
- Исправить установленную причину в её владельце; сохранить принятый поиск по ФИО и ролевое ограничение поиска по телефону.
- Закрепить наблюдаемый сценарий регрессионной проверкой; не внедрять новый алгоритм поиска без доказанной необходимости.

## Out of scope
Нечёткий поиск, транслитерация, изменение прав и состава фильтров, переделка списка.

## Constraints
Сервер определяет область доступных клиентов. Не фильтровать только загруженную страницу на клиенте. Если на текущем стенде пример не воспроизводится, зафиксировать различие данных/версии до выбора исправления.

До изменения кода нужен готовый план по docs/HARNESS.md. Визуальные решения проходят применимые этапы docs/DESIGN_PROCESS.md и выбор на проверенном прототипе. Этот разбор не утверждает прототип и не разрешает реализацию. При реализации актуализировать затронутые REQ и docs/requirements/CHANGELOG.md.

## Acceptance criteria
- [ ] При одинаковых фильтрах запросы «Алексеев», «Алексеев Алексей» и полное ФИО возвращают доступного «Алексеев Алексей Дмитриевич».
- [ ] Поиск с несколькими пробелами и разным регистром сохраняет действующий контракт; очистка запроса и возврат из карточки работают.
- [ ] Сотрудник не получает чужих клиентов или запрещённый ему поиск по телефону.

## Test checklist
- [ ] Сохранить воспроизводимый пример до исправления и результат после; проверить выдачу после завершения загрузки.
- [ ] Проверить одинаковые/длинные фамилии, несколько частей ФИО, пустую выдачу, пагинацию, смену запроса во время загрузки и разрешённые/запрещённые роли.
