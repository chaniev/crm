# TASK-206: Согласовать отображение филиала администратора в списке и диалоге

## Status
done

## Requirements
- REQ-USR-002 — implements
- REQ-USR-001 — constrains

## Goal
Список и диалог показывают одну достоверную область работы сотрудника.

## Context
ADM-01: у Администратора 01 список показывает «Филиал: не назначен», загруженный диалог «Группы посещений» — «Филиал: Филиал Центр». Внешний список сохраняет прежний текст. Проверка 21.11.2026 на main bf14d61 в изолированном тестовом API установила причину. Список и детали возвращают назначенный branchId и branchName: null, поскольку запросы не загружают связанный филиал. Для той же записи attendance-groups возвращает ID и имя филиала. Список подставляет «не назначен» при отсутствии имени.

## User role
Главный тренер и другие роли с backend-разрешённым доступом к настройкам администраторов.

## Problem
Сотрудник получает противоречивые сведения об области работы администратора.

## Scope
- Сопоставить серверные ответы списка, данных сотрудника и attendance-scope для одной учётной записи.
- Исправить подтверждённый дефект чтения/маппинга/обновления в соответствующем слое.
- Различать действительное отсутствие назначения, загрузку и ошибку, не угадывая филиал.

## Out of scope
Переназначение филиала, изменение доступа, запись новых групп посещений, миграции или исправление данных без отдельного решения.

## Constraints
Backend остаётся владельцем филиала и прав. Не выбирать первый филиал и не копировать название из другого сотрудника. Если для исправления необходимы изменения прав или хранимых данных, остановить зависимую реализацию и вернуть план на согласование.

До изменения кода нужен готовый план по docs/HARNESS.md. Визуальные решения проходят применимые этапы docs/DESIGN_PROCESS.md и выбор на проверенном прототипе. Этот разбор не утверждает прототип и не разрешает реализацию. При реализации актуализировать затронутые REQ и docs/requirements/CHANGELOG.md.

## Acceptance criteria
- [x] При успешной загрузке список и диалог одной учётной записи показывают согласованный филиал из серверных данных.
- [x] Сбой или неполный ответ не отображается как достоверное «не назначен».
- [x] Супер-администратор без обязательного филиала отображается корректно; доступные действия и права прежние.

## Test checklist
- [x] Проверить назначенный филиал, отсутствие применимого назначения, задержку и ошибку загрузки, обновление списка после существующего разрешённого изменения.
- [x] Проверить потребителей затронутого read-контракта; не подтверждать отсутствие авторизационных проблем одним визуальным снимком.
