# TASK-208: Упростить строки журнала и окно «Детали»

## Status
done

## Requirements
- REQ-AUD-002 — changes
- REQ-NFR-001 — constrains

## Goal
Сотрудник находит событие по времени, описанию и ФИО автора. В деталях он может сравнить старые и новые значения.

## Context
AUD-01: в строке рядом с описанием выводятся техническое действие, тип объекта, UUID и источник; на телефоне описание обрезается. REQ-AUD-002 уже требует убрать технические объект/действие из списка. Завершённые TASK-057/099 удаляли отдельные колонки; текущая находка относится к метаданным внутри строки.

## User role
Сотрудник с разрешённым доступом к журналу.

## Problem
Диагностические данные вытесняют полезное описание события.

## Scope
- Убрать технический код действия, тип объекта и UUID объекта из строки и окна «Детали», включая доступные имена элементов. В деталях показывать название действия, если для него есть перевод. При неизвестном действии использовать сохранённое описание события.
- В поле автора строки и деталей, а также в вариантах фильтра по сотруднику показывать только ФИО. Выбор сотрудника по-прежнему привязан к его идентификатору.
- Для событий из веб-интерфейса метка источника `Web` отображается только в деталях записи.
- Убрать отдельные метки «Бот» и «Telegram» из строки журнала и окна «Детали». Сохранить выбор источника и мессенджера в фильтрах.
- Сохранить время, описание, отдельного автора, фильтры, пагинацию и открытие деталей.

## Out of scope
Изменение audit payload/хранения, перезапись исторических описаний, новые переводы неизвестных действий (TASK-185), изменение состава фильтров и остальной редизайн деталей.

## Constraints
Сохранять исходные данные аудита, права доступа и содержимое старых и новых значений. Не переписывать сохранённые строки ради удаления повторного имени автора. Escape/возврат фокуса и доступность деталей сохраняются.

До изменения кода нужен готовый план по docs/HARNESS.md. Визуальные решения проходят применимые этапы docs/DESIGN_PROCESS.md и выбор на проверенном прототипе. Этот разбор не утверждает прототип и не разрешает реализацию. При реализации актуализировать затронутые REQ и docs/requirements/CHANGELOG.md.

## Acceptance criteria
- [x] В рабочих строках mobile/desktop нет технического объекта, UUID и дублирующего кода действия; описание и автор читаемы.
- [x] Автор указан только по ФИО в строке, деталях и фильтре по сотруднику. Выбор сотрудника фильтрует записи по прежним правилам.
- [x] На телефоне и компьютере кнопка «Детали» открывает описание, ФИО, дату и время, старые и новые значения. Метка `Web` видна только в деталях.
- [x] Событие из бота видно в списке и открывается за одно действие. Метки «Бот» и «Telegram» скрыты в строке и деталях. Каждый из двух фильтров позволяет найти событие.
- [x] Для известного и неизвестного действия технический код, тип объекта (включая переведённое название) и UUID объекта отсутствуют в метаданных записи и их доступных подписях. В деталях известного действия видно его переведённое название.
- [x] Фильтры по типу действия, пагинация, клавиатура и возврат фокуса работают как прежде.
