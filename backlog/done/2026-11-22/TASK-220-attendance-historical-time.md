## Goal
Читать время занятия из исторических данных при работе с посещениями.

## Context
Отметка хранит LessonOccurrenceId. Клиентская история и расчёт серии пропусков используют время группы. У двух занятий одной группы в один день оно совпадает.

## Acceptance criteria
- [x] После изменения графика история сохраняет фактическое время отмеченного занятия.
- [x] При двух занятиях в один день серия пропусков и граница «Связались» упорядочены по историческому времени. Проверена согласованность Staff API и бота.

## Constraints
Источник локального времени — сохранённое занятие, связанное с отметкой. Расчёт использует эту связь для любой даты занятия.

## Уточнение владельца от 22.11.2026
В чате планирования владелец исключил отдельный сценарий для данных до TASK-220. Восстановление неизвестного времени, обработка неоднозначных старых отметок и пересчёт ранее сохранённых границ «Связались» выходят за рамки задачи.

## Проверка доменного риска при планировании
В действующей схеме отметка имеет обязательную ссылку на занятие с сохранённым временем начала. Оба пути записи посещений используют занятие. Расхождение возникает при чтении истории, расчёте серии и выборе последней обработанной отметки. Риск и проверки описаны в [плане](TASK-220-attendance-historical-time.plan.md).

## Приёмка

На исходной версии история показывала время группы 12:00 для всех отметок. При большем ID утренней отметки серия ошибочно менялась с трёх пропусков на два и наоборот. В PostgreSQL подтверждение ссылалось на утреннее занятие.

На версии `a765d392` отметки через Staff API и Internal Bot API дали один порядок для тренера при смене графика и редактировании утреннего статуса. Проверены пределы доступа и постраничная выдача. В PostgreSQL подтверждение и аудит сохранили вечернюю отметку в 18:00 один раз. Из двух внесённых после контакта пропусков той же даты в новую серию вошёл только пропуск за 20:00. Причина вернулась на третьем пропуске.

Проверки потребителей подтвердили порядок строк при догрузке в вебе и вывод первых пяти записей в карточке Telegram. На итоговой версии прошли 859 серверных тестов, 835 модульных тестов веба, 74 теста бота и 48 браузерных проверок в Chromium и двух профилях iPhone WebKit. [Отчёт проверок](TASK-220-evidence/verification.json).
