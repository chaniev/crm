# TASK-072: Уточнить привязку абонементов к филиалам

## Status
done

## Goal
Зафиксировать, что набор абонементов задаётся на уровне филиала, а не зала, и перенести это требование в `TASK-070`.

## Context
Исходная заметка говорила о привязке абонементов к залам. После уточнения зафиксировано точное правило: у каждого филиала свой набор абонементов; отдельная привязка к залам не нужна.

## User role
Администратор / клиент / неизвестно.

## Problem
Неоднозначная формулировка могла привести к ошибочной hall-level модели вместо требуемого филиального каталога.

## Scope
- Зафиксировать филиал как уровень каталога абонементов.
- Исключить отдельную привязку к залам.
- Перенести требование в `TASK-070`.

## Out of scope
- Реализация backend, frontend или bot до уточнения требований.
- Изменение существующей связи абонемента с филиалом.
- Изменение каталога абонементов из `TASK-070` без подтверждённой продуктовой модели.

## Constraints
- Backend остаётся источником истины для memberships, attendance, access scope и validation semantics.
- Зал должен принадлежать тому же филиалу, если связь абонемента с филиалом сохраняется.
- Нельзя ломать исторические продажи, посещения и финансовые отчёты при изменении или архивировании зала.
- Изменение backend-контракта требует обновления всех потребителей.
