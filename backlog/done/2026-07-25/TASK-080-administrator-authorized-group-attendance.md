# TASK-080: Разрешить администратору отмечать посещения в назначенных группах

## Status
done

## Goal
Администратор может отмечать посещения только в явно разрешённых ему группах своего филиала, а главный тренер и суперадминистратор могут управлять этими разрешениями.

## Context
Первоначальная заметка «У администратора нет вообще функции отметить группу» не позволяла отличить attendance от состояния занятия и определить access scope. Новая заметка уточняет, что речь именно об отметке посещений, разрешение выдаётся на отдельные группы, выбирать можно только группы филиала администратора, а выдавать разрешение могут главный тренер и новая роль суперадминистратора из TASK-082.

В текущей реализации `CanMarkAttendance` для Administrator равен `false`, а backend group access разрешает все группы HeadCoach и назначенные группы Coach, но всегда отклоняет Administrator. Требование нельзя реализовать только видимостью UI: необходим backend-owned permission scope.

## User role
Администратор / главный тренер / суперадминистратор.

## Problem
Администратор не может вести посещаемость даже для доверенных ему групп. Простое включение общего `CanMarkAttendance` выдаст доступ шире требуемого и нарушит филиальные ограничения.

## Scope
- Добавить backend-owned назначение групп, посещаемость которых вправе отмечать конкретный Administrator.
- Разрешать выбирать для назначения только группы филиала, к которому относится Administrator.
- Разрешить HeadCoach и SuperAdministrator выдавать и отзывать такие назначения.
- Разрешить Administrator открывать attendance-сценарий и читать/изменять отметки только назначенных групп.
- Возвращать эффективный attendance scope в auth/session и прочих затронутых контрактах без дублирования правил на frontend или в bot.
- Добавить управление назначениями в пользовательский сценарий настройки администратора.
- Аудировать выдачу и отзыв разрешений с actor, administrator, group, branch и временем.
- Согласовать интеграцию с TASK-082: до появления SuperAdministrator выдача разрешений должна оставаться доступной HeadCoach.

## Out of scope
- Предоставление Administrator доступа ко всем группам филиала без явного назначения.
- Предоставление доступа к группам другого филиала.
- Изменение прав Coach или HeadCoach на отметку посещений.
- Реализация состояния занятия `Held`/`NotHeld` из TASK-075.
- Изменение списаний абонементов, допустимых дат attendance или других attendance semantics.
- Общая переработка ролей вне интеграции с TASK-082.

## Constraints
- Backend владеет ролями, permissions, branch/group access scope, attendance, validation и audit semantics.
- Булевый `CanMarkAttendance` не должен становиться единственным основанием для доступа Administrator к произвольной группе.
- Назначение группы другого филиала должно отклоняться атомарно стабильным ProblemDetails.
- Смена филиала Administrator не должна оставлять действующие назначения из прежнего филиала; точное поведение очистки или отклонения смены нужно закрепить до реализации.
- Изменение backend-контракта требует обновить все затронутые frontend и bot consumers.
- Разрешение на attendance не даёт Administrator других прав на группу, расписание, сотрудников или филиал.

## Acceptance criteria
- [x] HeadCoach может назначить Administrator одну или несколько групп его филиала для отметки посещений.
- [x] После реализации TASK-082 то же действие доступно SuperAdministrator.
- [x] В списке назначения отсутствуют группы других филиалов.
- [x] Administrator видит в attendance-сценарии только назначенные ему группы.
- [x] Administrator может читать и сохранять отметки назначенной группы в пределах действующих правил дат и membership semantics.
- [x] Прямой API-запрос к неназначенной группе или группе другого филиала возвращает согласованный отказ без изменений данных.
- [x] Отзыв разрешения немедленно прекращает доступ и фиксируется в audit.
- [x] Смена филиала не сохраняет скрытый доступ к группам прежнего филиала.
- [x] Права HeadCoach и Coach не регрессируют, а TASK-075 не дублируется.
