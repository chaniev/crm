# TASK-075: Отмечать занятие как непроведённое

## Status
done

## Goal
Дать администратору и главному тренеру возможность явно зафиксировать на экране посещаемости, что занятие группы в выбранную дату не проводилось, и при необходимости восстановить его состояние.

## Context
Функциональность первоначально входила в TASK-067, но продуктовая подсветка повторных пропусков является рекомендательной и не требует точной модели ожидаемых занятий. Поэтому состояние занятия, его история и аудит вынесены в самостоятельную задачу и не влияют на missed-training streak TASK-067.

## User role
Администратор / главный тренер.

## Problem
Сейчас CRM хранит только отдельные attendance-отметки и не имеет самостоятельного аудируемого факта, что занятие группы в конкретную дату проводилось или было отменено.

## Scope
- Добавить backend-owned состояние занятия для пары `group + training date`.
- Разрешить Administrator и HeadCoach явно переключать состояние `Held`/`NotHeld`.
- Обеспечить уникальность записи для пары `group + training date` и аудит каждого изменения состояния.
- Добавить один UI-вход на экране посещаемости: `Занятие не проводилось` / `Восстановить занятие`.
- Определить согласованное поведение существующих attendance-отметок при переводе занятия в `NotHeld` и обратно.

## Out of scope
- Влияние `Held`/`NotHeld` на missed-training streak из TASK-067.
- Автоматическое определение `NotHeld` по полностью `Unmarked` ведомости.
- Второй UI-вход из расписания; при необходимости он оформляется отдельно.
- Snapshot ожидаемых участников, пока его не потребует отдельный утверждённый сценарий.

## Constraints
- Состояние занятия и его аудит принадлежат backend.
- `Unmarked` не означает автоматически, что занятие не проводилось.
- Простое открытие ведомости не создаёт и не изменяет состояние занятия.
- Frontend не восстанавливает effective state из attendance-отметок.

## Acceptance criteria
- [ ] Administrator и HeadCoach могут отметить выбранное занятие непроведённым на экране посещаемости.
- [ ] Те же роли могут восстановить занятие как проведённое.
- [ ] Остальные роли не могут менять состояние занятия.
- [ ] Для одной группы и даты существует не более одной записи состояния.
- [ ] Все переходы состояния аудитируются.
- [ ] Полностью `Unmarked` ведомость сама по себе не меняет состояние занятия.
- [ ] Состояние занятия не влияет на missed-training streak TASK-067.

## Test checklist
- [ ] Покрыть создание, повторную команду, восстановление и concurrency.
- [ ] Проверить роли, branch scope, CSRF и audit payload.
- [ ] Проверить поведение при уже существующих `Present`/`Absent` и последующих исправлениях.
- [ ] Проверить UI-состояния, ошибку команды и повторную загрузку ведомости.
