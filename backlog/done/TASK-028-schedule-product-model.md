# TASK-028: Уточнить модель расписания

## Status
done

## Goal
Понять, какое расписание нужно CRM: групповые занятия, тренеры, филиалы, залы и график занятий по группам.

## Context
В inbox есть короткая заметка: `Расписание`.

Уточнение от 2026-05-07:
- расписание по секциям для тренеров должно формироваться автоматически после заполнения карточек.
- У группы нужно выбрать тип группы, филиал, зал, время начала и продолжительность занятия.
- По `TASK-022` группа может быть только в одном филиале, зал выбирается внутри филиала, а зал нельзя удалить или архивировать, если к нему привязано расписание.

Уточнение от 2026-05-13:
- Расписание нужно только для групповых занятий.
- Источник расписания - график занятий по группам.
- Расписание формируется автоматически на основе графика занятий по группам.
- Переносы, отмены и замены тренера не обрабатываются в этой модели.
- Занятость зала и конфликты времени не проверяются в этой модели.
- Связь расписания с отметкой посещаемости и уведомлениями не нужна в этой модели.

## User role
администратор / тренер / владелец / неизвестно

## Problem
Ключевые правила расписания уточнены. Реализация вынесена в отдельные risky-задачи для backend и frontend.

## Scope
- Зафиксировать, что расписание относится только к групповым занятиям.
- Зафиксировать, что источником расписания является график занятий по группам.
- Зафиксировать автогенерацию расписания на основе графика занятий по группам.
- Зафиксировать, что персональные тренировки, переносы, отмены, замены тренера, проверки конфликтов, посещаемость и уведомления не входят в текущую модель.
- Зафиксировать обязательные поля группы для расписания: тип группы, филиал, зал, время начала и продолжительность занятия.
- Учесть правила филиалов и залов из `TASK-022` / `TASK-031`.
- Разбить уточненную модель на implementation tasks.

## Out of scope
- Немедленная реализация расписания.
- Персональные тренировки.
- Переносы, отмены и замены тренера.
- Проверка занятости зала и конфликтов времени.
- Изменение посещаемости.
- Уведомления и bot notifications.

## Constraints
- Автоматическое формирование расписания должно опираться на backend-данные и backend-валидацию группы, а не на frontend-only логику.
- Филиалы и залы должны использовать backend rules из `TASK-031`, без frontend/bot дублирования.
- Если позже появятся переносы, отмены, замены тренера, проверки конфликтов, посещаемость или уведомления, эти правила должны быть вынесены в отдельные задачи и принадлежать backend domain logic.
- Нужно предусмотреть migrations и contract validation для новых полей графика занятий группы.
