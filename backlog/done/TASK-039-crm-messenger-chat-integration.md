# TASK-039: Уточнить интеграцию чатов с клиентами из мессенджеров в CRM

## Status
done

## Goal
Понять, какие клиентские чаты из мессенджеров должны появиться в CRM, как ими будут пользоваться сотрудники и какие технические ограничения нужно учесть до реализации.

## Context
В inbox есть короткая заметка про настройку интеграции чатов с клиентами из мессенджеров в CRM. После уточнения 2026-05-21 первый канал для MVP - Telegram через отдельный официальный Telegram bot клуба, сценарий - полноценный двусторонний текстовый чат администратора с клиентом внутри карточки клиента.

## User role
администратор / тренер / владелец / неизвестно

## Problem
CRM может не давать единого места для переписки с клиентами, но без уточнения сценария Codex пришлось бы придумывать продуктовую модель, права доступа и интеграционные правила.

## Scope
- Первый мессенджер MVP: Telegram.
- Канал MVP: отдельный официальный Telegram bot клуба, не личный аккаунт администратора, не Telegram Business account и не текущий Telegram-бот сотрудников CRM.
- Реализовать полноценный двусторонний текстовый чат администратора с клиентом.
- Отображать чат в карточке клиента.
- Привязывать клиентский Telegram-аккаунт к клиенту CRM через одноразовую ссылку/deep link из CRM и QR-код с той же ссылкой.
- Дать доступ к чтению администратору и главному тренеру.
- Дать право отвечать любому администратору.
- Поддержать локальные статусы отправки CRM/Telegram: "отправляется", "отправлено в Telegram", "ошибка". Telegram-level delivery/read receipts не входят в MVP Telegram bot, потому что Bot API не дает надежных обычных статусов доставки/прочтения клиентом.
- Показывать in-app уведомления/индикаторы новых сообщений в CRM.
- Логировать просмотр переписки.
- Хранить переписку, пока запись клиента есть в базе.

## Out of scope
- Немедленная реализация интеграции.
- Выбор конкретного провайдера без продуктовых и инфраструктурных требований.
- Смешивание клиентского чата с текущим Telegram-ботом сотрудников CRM.
- Автоматические рассылки и маркетинговые кампании.
- Импорт старой истории сообщений из Telegram.
- Вложения, документы, голосовые, видео, stickers/emoji как отдельные типы сообщений.
- Назначение диалогов на сотрудников, статусы "открыт/закрыт", поиск и фильтры в MVP.

## Constraints
- Backend должен владеть правилами доступа, связями клиента с внешними идентификаторами, аудитом и validation semantics.
- Интеграция с мессенджерами может затронуть персональные данные, webhooks, delivery correctness, retries, фоновые задачи и production-инфраструктуру.
- Нельзя хранить или показывать переписку без явных правил доступа и retention.
- Клиентская Telegram-интеграция должна быть отделена от существующего Telegram-бота сотрудников CRM; предпочтительно использовать отдельный Telegram bot/token и отдельные runtime-настройки.
- MVP не использует обычный Telegram user-account клуба, MTProto-автоматизацию пользовательского аккаунта или Telegram Business connected bot.
- У клиента может быть один аккаунт в рамках одного мессенджера, но в будущем у клиента может быть несколько разных мессенджеров.
- Access scope по филиалу, группе, назначенному тренеру или статусу клиента для MVP не требуется.
