# TASK-026: Уточнить статистику и финансовые отчеты

## Status
done

## Goal
Сформировать понятный набор статистических и финансовых отчетов с определениями метрик, периодами и фильтрами.

## Context
В inbox есть заметка: `Статистика (количество проданных абонементов по филиалам, количество новых клиентов, финансовый отчет (за мес, год)...)`.

Уточнение от 2026-05-07:
- расчет по тренеру должен строиться на том, сколько абонементов было куплено на тренировки конкретного тренера.
- отчеты по филиалам остаются отдельной задачей относительно внедрения филиалов;
- после уточнения `TASK-022` абонемент считается привязанным к филиалу клиента.

Уточнение от 2026-05-13:
- первый релиз должен включать отчет по количеству проданных абонементов за разные периоды с учетом филиалов и тренеров;
- первый релиз должен включать отчет по количеству новых клиентов с выбранной даты;
- `проданный абонемент` считается по дате покупки;
- для возврата должна быть возможность указать сумму возврата;
- `нулевые` абонементы считаются отдельными абонементами, но при расчете общей суммы их стоимость равна `0`;
- быстрые периоды: месяц, квартал, год; дополнительно нужен произвольный период;
- финансовые данные может видеть роль `главный тренер`;
- отмены и заморозки на этом этапе не учитываются в отчетах;
- у возврата должна фиксироваться дата возврата, возвраты считаются по дате возврата;
- новый клиент считается по дате покупки нового абонемента;
- по филиалам должна быть возможность получить информацию как по отдельному филиалу, так и по всем филиалам сразу;
- тренер назначается на группу, поэтому количество абонементов по тренеру считается через группы, которые он ведет;
- в главном меню должна быть отдельная вкладка `Финансы`;
- в первом релизе нужно показывать все три финансовых показателя: валовая сумма продаж, сумма возвратов и чистая сумма.

## User role
владелец / администратор / главный тренер

## Problem
Запрос на статистику и финансовые отчеты уточнен и разбит на отдельные implementation tasks.

## Scope
- Зафиксировать список отчетов первого релиза: проданные абонементы по периодам с учетом филиалов и тренеров, новые клиенты с выбранной даты.
- Зафиксировать метрику по тренеру: количество купленных абонементов на тренировки конкретного тренера и производные финансовые показатели.
- Зафиксировать периоды: месяц, квартал, год, произвольный диапазон.
- Зафиксировать фильтр филиала: отчет доступен как по отдельному филиалу, так и по всем филиалам сразу.
- Зафиксировать источник связи `покупка абонемента -> тренировки конкретного тренера`: тренер назначается на группу, абонементы по тренеру считаются через группы, которые он ведет.
- Учесть, что филиал для абонемента берется из филиала клиента согласно `TASK-022`.
- Зафиксировать правила финансового отчета: продажа по дате покупки, возвраты с указанием суммы и даты возврата, возвраты считаются по дате возврата, нулевые абонементы учитываются в количестве и дают `0` в общей сумме, отмены и заморозки на первом этапе не учитываются.
- Показывать в финансовом отчете валовую сумму продаж, сумму возвратов и чистую сумму.
- Разместить отчеты в отдельной вкладке `Финансы` в главном меню.
- После ответов разбить на отдельные risky implementation tasks.

## Out of scope
- Немедленная реализация отчетов.
- Расчет финансовых метрик без согласованных определений.

## Constraints
- Backend владеет financial report semantics.
- Расчет по тренеру должен выполняться backend-логикой на основе согласованной связи абонемента с тренировками конкретного тренера.
- Филиалы уточнены в `TASK-022`; implementation dependency: `TASK-031`.
- Нельзя дублировать финансовые формулы во frontend.

## Financial totals terminology
- Валовая сумма продаж: сумма стоимости абонементов, купленных за выбранный период по дате покупки; возвраты из нее не вычитаются, `нулевые` абонементы дают `0`.
- Сумма возвратов: сумма указанных возвратов, дата возврата которых попадает в выбранный период.
- Чистая сумма: валовая сумма продаж за выбранный период минус сумма возвратов за выбранный период.
