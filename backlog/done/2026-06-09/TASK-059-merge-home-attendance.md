## Goal
Сделать `Главную` единственным входом для текущей главной страницы и отметки посещений: форма посещений переезжает на `Главную`, отдельная вкладка `Посещения` и URL `/attendance` удаляются.

## Context
В inbox зафиксирована заметка: `объединить главная и посещение`. После уточнения принято решение не группировать разделы и не делать отдельный URL, а перенести рабочий сценарий отметки посещений на `Главную`.

Текущая система имеет отдельные frontend-экраны `HomeDashboard` и `AttendanceScreen`, отдельную секцию `Attendance`, путь `/attendance`, e2e-покрытие для `/attendance` и backend-driven `allowedSections`.

## User role
администратор / главный тренер / тренер

## Product decisions
- Новый и единственный пункт меню для объединенного сценария: `Главная`.
- Все роли затрагиваются.
- Для тренера на `Главной` должна быть доступна только отметка посещений.
- Тренер после входа должен сразу попадать к отметке посещений.
- Для администратора в первую очередь важен блок истекающих абонементов.
- Блок истекающих абонементов остается на `Главной`.
- Форма отметки посещений добавляется на `Главную`.
- Группа, дата и список клиентов для отметки посещений должны быть видны сразу, без дополнительных кликов.
- В мобильной навигации должен остаться только пункт `Главная` вместо пары `Главная` + `Посещения`.
- URL `/attendance` должен быть удален полностью.
- Backend больше не должен возвращать пользователю секцию `Attendance`.
- Если не загрузились истекающие абонементы, отметка посещений продолжает работать.
- Если не загрузились данные посещений, блок истекающих абонементов продолжает работать.

## Problem
Сейчас `Главная` и `Посещения` разнесены по разным пунктам меню и маршрутам. Это создает лишнюю навигацию для сценария, который должен быть доступен с главного экрана, особенно для тренеров, которым важно сразу перейти к отметке посещений.

## Scope
- Обновить backend access scope/session contract так, чтобы `Attendance` больше не возвращался в `allowedSections`, а доступ к отметке посещений оставался управляемым backend permissions.
- Обновить frontend типы, маршрутизацию и навигацию под удаление секции `Attendance` и URL `/attendance`.
- Перенести или переиспользовать UI отметки посещений внутри `Главной`.
- Сохранить блок истекающих абонементов на `Главной` для администратора и главного тренера.
- Сделать состояние загрузки/ошибки истекающих абонементов независимым от состояния загрузки/ошибки посещений.
- Обеспечить тренеру landing на `Главную` с сразу видимой отметкой посещений.
- Обновить unit/e2e-тесты маршрутизации, навигации и сценария отметки посещений.

## Out of scope
- Изменение backend-семантики отметки посещений.
- Изменение правил attendance, roles, permissions и audit вне удаления frontend-секции `Attendance` из access scope.
- Переработка сценария сохранения посещений.
- Удаление других пользовательских разделов без отдельного решения.

## Constraints
- Backend остается источником истины для roles, permissions и access scope.
- Frontend не должен дублировать доменные правила доступа к посещаемости.
- Быстрый сценарий отметки посещений для тренеров и администраторов не должен ухудшиться.
- Для будущей реализации создать отдельную ветку от `main`, например `feature/TASK-059-merge-home-attendance`.
- При frontend-изменениях следовать `frontend/AGENTS.md` и сохранить Mantine/Onest.
- При backend-изменениях следовать `backend/AGENTS.md`.

## Acceptance criteria
- [ ] В навигации больше нет отдельной вкладки `Посещения`.
- [ ] В мобильной навигации вместо `Главная` + `Посещения` остается только `Главная`.
- [ ] URL `/attendance` удален и больше не используется как рабочий маршрут.
- [ ] Backend больше не возвращает `Attendance` в `allowedSections`.
- [ ] Тренер после входа попадает на `Главную` и сразу видит отметку посещений.
- [ ] На `Главной` тренера доступна только отметка посещений в рамках объединенного экрана.
- [ ] Администратор и главный тренер видят блок истекающих абонементов на `Главной`.
- [ ] Форма отметки посещений доступна на `Главной` для ролей с правом отметки посещений.
- [ ] Группа, дата и список клиентов для отметки посещений видны сразу, без раскрытия дополнительных вкладок или переходов.
- [ ] Ошибка загрузки истекающих абонементов не блокирует отметку посещений.
- [ ] Ошибка загрузки посещений не блокирует блок истекающих абонементов.
- [ ] Семантика сохранения посещений не изменилась.
