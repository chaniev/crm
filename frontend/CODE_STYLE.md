# Кодстайл TypeScript и React

## Соглашения для разработки и ревью

- В `.ts` и `.tsx` следуйте оформлению соседнего кода. Обычный стиль проекта — отступ в 2 пробела, одинарные кавычки для строк TypeScript и строки кода без завершающей точки с запятой. Эти детали проверяются при чтении кода. [Пример хука](src/features/users/useUserFormErrorFocus.ts)
- Называйте React-компоненты в `PascalCase`, функции и переменные в `camelCase`. Имена хуков начинайте с `use`, например `useUserFormErrorFocus`.
- Держите компоненты и хуки рядом со сценарием, который они обслуживают. При повторном использовании интерфейса между сценариями проверьте существующие общие компоненты. [Правила структуры frontend](AGENTS.md#structural-rules)

## Автоматические проверки

- ESLint применяет рекомендованные правила JavaScript, TypeScript и React Hooks, а также правила React Refresh для Vite. Вызывайте хуки состояния и эффектов на верхнем уровне компонента или хука и указывайте используемые реактивные значения в зависимостях эффекта. [Конфигурация ESLint](eslint.config.js)
- В исходниках приложения включён строгий режим TypeScript. Помечайте импорты, используемые только как типы, через `import type` или `type` внутри списка импортов. Компилятор также проверяет неиспользуемые локальные переменные и параметры. [Конфигурация TypeScript](tsconfig.app.json)

Проверка frontend включает линтинг, типизацию и проектные проверки цветов, отступов интерфейса и пользовательских текстов. [Состав проверки](package.json) · [Порядок запуска](../docs/HARNESS.md)
