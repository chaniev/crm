# Порядок запуска, миграций и развёртывания

Читать только при изменении схемы, данных, среды выполнения или явном обновлении стенда.

## Миграции

1. Определить поддерживаемую исходную схему и механизм миграций.
2. Не переписывать уже применённые миграции.
3. Для одной новой миграции проверить обновление от поддерживаемой предыдущей
   схемы; отдельный прогон каждой миграции не нужен.
4. Для нескольких новых миграций проверить упорядоченную цепочку и последовательно
   менять общий снимок модели и метаданные.
5. Проверить преобразование существующих данных, обязательные значения по умолчанию,
   порядок ограничений и сохранность данных.
6. Проверять развёртывание с нуля только при поддержке проекта.

Копия развёрнутой БД и резервная копия нужны только для проверки реальных данных
или обновления общей среды. Для временной БД задачи без ценных данных резервную
копию не создавать.

## Среда выполнения задачи

Запускать изолированную среду Compose только если тесты и сборка не дают
необходимых доказательств: меняются контракт запуска, миграция, конфигурация,
состояние сервисов или их интеграция. Для статических и компонентных задач
запущенную среду не создавать.

Использовать уникальные имя проекта, порты, сеть и тома. Старую схему
с характерными данными готовить только для проверки миграции и совместимости
данных. В других случаях допустима чистая временная БД.

Проверять только применимое: историю миграций, готовность и состояние,
ошибки журналов, сохранность данных и основной изменённый сценарий.

## Развёртывание

Выполнять только для явно заданной цели. Промышленная среда требует отдельного
явного разрешения.

Для общей БД до потенциально необратимого действия подтвердить резервную копию
и откат/восстановление. Использовать стратегию проекта; по умолчанию:

`резервная копия -> упорядоченная миграция/расширение -> развёртывание точного образа/SHA -> проверка состояния -> проверка основных сценариев`

Если миграцию запускает приложение или команда развёртывания, не применять её
повторно; проверить историю и фактическую схему. Для expand/contract соблюдать
предусмотренные этапы заполнения данных и сужения контракта.

После развёртывания записать цель, точный образ/SHA, версию схемы, состояние
и результат проверки основных сценариев. Не продолжать разрушительную миграцию
при риске потери данных без проверяемого восстановления.
