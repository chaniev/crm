# Кодстайл C# и .NET

## Форматирование и анализаторы

- Используйте 4 пробела для отступа. Открывающую фигурную скобку ставьте на новой строке. Ключевые слова `else`, `catch` и `finally` также начинайте с новой строки.
- В списке `using` ставьте пространства имён `System` первыми. Сохраняйте один блок без пустых строк между группами и удаляйте неиспользуемые директивы. [Настройки редактора и форматтера](../.editorconfig)
- Отмечайте ссылочные типы, допускающие `null`, с помощью `?`. В проекте включены nullable-анализ и анализаторы .NET. Сборка считает предупреждения ошибками. [Настройки сборки](Directory.Build.props)

## Соглашения для разработки и ревью

- Предпочитайте один тип верхнего уровня на файл. Выбирайте для файла имя типа. Используйте `PascalCase` для типов и методов, `camelCase` для параметров и локальных переменных.
- Давайте сервису или модулю эндпоинтов одну понятную ответственность. Выносите вложенный вспомогательный тип, когда его связь с родительским типом перестаёт быть очевидной. [Правила структуры backend](AGENTS.md#structural-rules)

При проверке backend репозиторий запускает `dotnet format` в режиме проверки и собирает решение в Release с анализаторами. [Порядок проверки](../docs/HARNESS.md)
